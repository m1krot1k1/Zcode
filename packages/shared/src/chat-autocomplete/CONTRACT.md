# shared-chat-autocomplete

Проводной контракт предиктивного автодополнения в композере (ghost-text).

Инварианты:

- `suggestion` — это **только суффикс-pродолжение** префикса до курсора. Он никогда не
  содержит уже введённый текст: `removePrefixOverlap` устраняет дублирование на BPE-границе.
- `suggestion` — продолжение **в голосе пользователя**, а не ответ ассистента.
  `detectAssistantVoiceSuggestion` / `filterAssistantVoiceSuggestion` детерминированно
  отбрасывают явные ассистентские планы («Сначала изучу…», «Затем проверю…», «I'll check…»,
  markdown-планы), не блокируя пользовательские конструкции («Сначала надо проверить…»).
- Ответ всегда однострочный: `clipGhostSuggestion` режет по первому переводу строки и
  отбрасывает комментарии кода, чтобы ghost-текст не превращался в многострочную вставку.
- `chatAutocompleteSettings.enabled` по умолчанию `true`; запрос ограничен дебаунсом,
  `minPrefixChars`, кэшем и бюджетом 48 выходных токенов.
- Модуль чистый (без IO): Zod-схемы, лимиты и детерминированные пост-обработчики.
  Вызов модели, кэш префиксов и профиль лексики живут в `services-chat-autocomplete`.
- Схемы `.strict()`: транспорт не добавляет собственных полей; неизвестное поле — ошибка контракта.
- `sanitizeForLexicon` — единственная точка допуска текста в профиль: секреты, письма,
  домашние пути и высокоэнтропийные токены вырезаются до записи в `user-lexicon.json`.

Точки пересечения модулей:

- `ui-lexical-ghost-autocomplete` вызывает `IChatAutocompleteService` только через свой hook и
  читает те же чистые функции пост-обработки (`takeNextWord`, `removePrefixOverlap`).
- Настройки автодополнения (`AppSettings.chatAutocomplete`) приходят в запрос как
  `context`/`debounceMs`/`modelSelection`; Host не угадывает значения.
