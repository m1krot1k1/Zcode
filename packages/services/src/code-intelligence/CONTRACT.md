# Code Intelligence service contract

`ICodeIntelligenceService` is the single owner of local code-index lifecycle and graph/search reads. The Host keeps SQLite under the local ZCode data root's `code-intelligence/` directory, keyed by SHA-256 of `workspaceIdentity?.trim() || workspacePath`; the UI and agent tools only receive relative paths and bounded, sanitized index facts.

## Schema v2, worker ownership, and AST parsing

Storage and parsing live in a dedicated `node:worker_threads` worker (`worker/indexWorker.ts`), so scanning, AST parsing, SQLite writes, graph ranking and search never block the Local Host event loop. The worker is the single owner of one `DatabaseSync` connection in WAL mode and validates every message with Zod (`worker/workerProtocol.ts`).

The schema is `schema_version = 2`: integer `file_id`/`symbol_id`/`chunk_id` primary keys, external-content FTS5 tables (`chunks_fts`, `symbols_fts`) that do not duplicate chunk text, `chunk_vectors` with a 256-byte Int8 local sketch, and `sketch_postings` as an inverted index for approximate vector candidates. A v1 database on disk is migrated explicitly: the legacy tables are dropped, v2 is created, the migration is recorded in `meta`, and `VACUUM` runs; the user's files are never touched and the index is rebuilt in the background.

Parsing uses `web-tree-sitter` WASM grammars for TypeScript/TSX, JavaScript/JSX, Python, Go, Rust, C/C++, C#, Java, Kotlin, Ruby, PHP, Bash, JSON, TOML, HTML, CSS and Vue. Languages without a working grammar in the shipped artifact (YAML, Markdown) and unknown text files are handled by a deterministic structural chunker (heading/indent/brace aware), never by a fixed line window. Chunks always start and end on line boundaries and never split an AST node; large declarations are split by their own members and carry a `scope_header` chain such as `path | Class.method`.

## Operations

- `getStatus` reads committed generation metadata and process-local progress. `databaseBytes`, `schemaVersion`, `migratedFromV1`, `legacySizeBytes` and `textFallbackFiles` are optional v2 fields; older consumers keep working.
- `watchWorkspace` arms one Host-owned `chokidar` watcher with pre-filtered ignore rules (no directory crawl before watch registration) and reconciles changes missed while the Host was closed. With `autoIndexOnOpen` (default `true`) an absent index is built in the background instead of staying `unindexed`; this closes the historic "never builds its first index" defect.
- `indexWorkspace` arms the watcher before scanning and publishes a complete generation. Unchanged files are skipped by mtime+size, so repeating it is a cheap no-op; `force` re-parses everything.
- `notifyFilesMutated` reconciles exact paths (`changed`/`removed`) without a rescan. It is fed by watcher batches and by committed file transactions (Increment 4.2) so edits arrive with zero debounce delay.
- `search` packs its result into a token budget before serialization, so the response is always valid JSON: when the budget cannot fit another excerpt the packer collapses it to a signature or drops it and reports `budget.dropped`/`budget.collapsed`. Byte-level truncation of the serialized payload is forbidden and no longer performed anywhere in the path.
- `search` runs four candidate channels — FTS5 BM25 (`bm25(chunks_fts, 4.0, 6.0, 1.0)` with `ORDER BY rank`), exact symbol/path lookup, the local 256-dimensional Int8 sketch (offline, always available) and one-hop graph expansion — then merges them with Reciprocal Rank Fusion (`k = 60`, weights `exact 1.35 / fts 1.15 / vector 1.00 / graph 0.65`), applies path-tier de-boosting (production `1.00`, docs `0.65`, tests `0.35`, fixtures/skills `0.20`, neutralised when the query itself mentions tests/docs/skills), a graph boost (`1 + 0.20·pagerank + 0.15·centrality`) and a proximity boost for active/changed files, merges adjacent spans, and finally packs the result into `maxTokens`. `partial` reports incomplete index coverage only; `budget.truncated` reports packing truncation, so the two states cannot be confused.
- `getSymbolContext`, `getImpact`, and `trace` query symbols and dependency edges from the same generation.
- Provider vectors are optional and never required: when an embedding provider is configured the full vector is projected by a deterministic signed random projection into the same 256 dimensions as the local sketch and quantized to Int8, so the vector channel reuses one postings index and one cosine routine (`sketch_postings.kind` distinguishes local `0` from provider `1`). Search never contacts the network unless a provider is configured and the Host resolved a stored credential for that request.
- Edges carry `defines`, `references`, `calls`, `imports`, `extends` and `implements`. Import aliases (`import { a as b }`) are resolved to the original symbol, and a call whose name came from an import is resolved against that module first, so a same-named symbol elsewhere cannot become a false target. Cross-file resolution is linear: names with exactly one definition are resolved through a single grouped pass, avoiding the per-row correlated subquery that made the pass quadratic.
- PageRank uses 15 deterministic iterations (`d = 0.85`) over the file import/call graph; edges from test files (`path_tier >= 2`) weigh `0.2` so mocks used heavily by tests do not outrank architecture. Symbol centrality is normalised `log1p(in · 2 + out)`.
- `getGraphOverview` returns a bounded connected overview seeded from a high-degree node or one focused symbol neighborhood, with relative paths and an explicit partial flag; it never returns source excerpts.
- `setEmbeddingConfig` configures or clears Ollama or an OpenAI-compatible endpoint/model and may save or clear an optional API key. It never installs or launches models. The local sketch keeps semantic ranking available with no provider configured.
- `testEmbeddingConfig` probes a fixed, non-source batch at the same maximum size used by indexing, with the draft provider config and saved/draft token. It never saves configuration or changes vectors, and returns only a sanitized outcome, dimensions, elapsed time, and (for HTTP failures) the status code; it never returns a provider response body.
- `clearIndex` closes and removes one identity-scoped database.

## State and failure behavior

SQLite owns non-secret workspace embedding metadata and index data. `ICredentialService` owns the API key under a credential key derived from the workspace identity hash. In-process indexing/embedding progress is ephemeral; the last embedding phase (`pending`, `ready`, or `failed`) is persisted so a restart cannot leave a false `building` status. A failed embedding build preserves lexical indexing, records only a safe error category and optional HTTP status in `CodeIndexStatus.embedding.lastError`, and leaves the previous vectors unpublished. The composer index popover prioritizes this error over coverage warnings. Provider response bodies, source text, and credentials never enter diagnostics. Retryable HTTP 429/5xx responses receive at most two bounded retries per batch, respecting a short provider `Retry-After`; a repeated failure remains visible and can be retried by refreshing the index. An index/storage failure rolls back content changes and leaves the previous committed generation queryable. Repeating a successful index against unchanged files is idempotent. A workspace identity is never inferred from display name. Omitted embedding settings preserve their saved values; null provider/endpoint/model explicitly clears the whole configuration, and `apiKey: null` clears only the key.

## Privacy and resource bounds

Only JS/TS-family source files up to 1 MiB are considered. Root and nested Git ignore rules and `.zcodeignore` apply, along with built-in dependency/build/secret exclusions. Symlinks are skipped. Absolute paths, source-root paths, credentials, and source text are not written to status or diagnostics. Embedding requests send source chunks and search queries to the configured endpoint; Ollama is limited to loopback HTTP, while OpenAI-compatible remote calls require HTTPS except for loopback HTTP. Requests are batched and response order is validated. Search and graph traversals return bounded results without materializing embedding blobs or the entire graph in application memory.

The workspace watcher uses one native recursive subscription rather than a per-directory recursive crawl. Unsupported or failed watcher creation is reported and leaves explicit manual refresh available; it does not fall back to a watcher per directory.
