## 1. Scope and method

### 1.1. Вопрос

Какие конкретные механики используют восемь коммерческих IDE-интегрированных агентов в части: архитектуры, agent loop, инструментов, стратегии контекста, разрешений и sandbox, расширяемости, субагентов и оркестрации, маршрутизации моделей, контроля затрат и лимитов, UX, телеметрии и evals, enterprise-развёртывания и модели ценообразования? Какие из этих механик стоит изучать, а какие являются антипаттернами? Ответ — только со стороны конкурентов; это вход для родительского синтеза, а не план внедрения в ZCode.

### 1.2. Продукты в охвате

1. Cursor (Anysphere; 2026-08-14 приобретён SpaceX, продаётся через The X Subscription).
2. Windsurf, теперь Devin Desktop (Cognition). Cascade — legacy-агент; Devin Local — текущий локальный harness.
3. GitHub Copilot: agent mode, Copilot in the cloud (ранее coding agent / cloud agent), Copilot CLI, code review, enterprise policy.
4. JetBrains AI: AI Assistant, Junie, Air, внешние агенты через ACP, cloud agents.
5. Zed AI: Zed Agent, External Agents через ACP, edit prediction, open-source редактор.
6. Kiro (AWS): specs, steering, hooks, permissions, powers, cloud sessions, enterprise management.
7. Trae: built-in Agent, SOLO, custom agents/subagents, режимы разрешений, sandbox.
8. Augment Code: Cosmos (Experts/Environments/Sessions/Triggers), Auggie CLI, Context Engine.

### 1.3. Вне охвата

- Автономные облачные агенты без IDE как основной поверхности (например, Devin Cloud как продукт, Amazon Q Developer), кроме случаев, когда это тот же harness, что и IDE-продукт.
- Open-source терминальные агенты и форки VS Code, покрытые соседними ветками (Cline, Roo, Kilo, Continue, OpenCode, Aider, Goose).
- Чистые completion-плагины без agent loop.
- Ручное тестирование, покупка тарифов, юридическая проверка, security-аудит и нагрузочное тестирование.

### 1.4. Правила доказательств

Каждое утверждение о конкуренте несёт прямой URL. Дата доступа ко всем URL — 2026-11-11, она повторена в §8. Статусы:

- **confirmed** — официальная документация, changelog, страница тарифов или публичный репозиторий прямо утверждают механику. Документация всё равно написана вендором: она доказывает, что вендор это документирует, а не что реализация совпадает.
- **claim** — маркетинговая страница или позиционирование без деталей реализации. Используется только при отсутствии документации и всегда помечается.
- **blocked** — URL вернул 404/403, оказался paywalled или редиректит на мёртвую страницу. Записывается в §8.3, а не заполняется по памяти.
- **inferred** — мой кросс-источниковый вывод. Всегда формулируется как «вывод» и никогда не подаётся как заявление вендора.

В тексте источники обозначаются как `(C1)`, `(W7)`, `(G12)`, `(J5)`, `(Z7)`, `(K10)`, `(T4)`, `(A3)`. Каждый ID соответствует ровно одной строке в §8: URL плюс дата доступа 2026-11-11. Для несущих механик URL также указан inline. Все ссылки были фактически запрошены в ходе этого ресёрча; ни одна не восстановлена по памяти.

### 1.5. Методические оговорки и известные искажения

- **Документация Trae — клиентский SPA.** `docs.trae.ai` отдаёт HTML-оболочку; английское тело статьи встроено JSON-пейлоадом документа. Я извлекал встроенный объект `content` для страниц `?lang=en`. Видимая страница может рендериться иначе, но цитируемые предложения взяты из пейлоада вендора, а не из стороннего пересказа. Маркеры списков в извлечённом тексте выглядят как артефакты `*` и были нормализованы.
- **Windsurf в середине ребрендинга.** `https://windsurf.com` отдаёт HTTP 308 на `https://devin.ai/desktop`; `https://docs.windsurf.com/windsurf/cascade/cascade` отдаёт HTTP 307 на `https://docs.devin.ai/desktop/cascade/cascade`. Поэтому продукт рассматривается как Devin Desktop, а Cascade явно помечен legacy. Старый enterprise-путь документации после редиректа отдаёт 404; это записано в §8.3.
- **Cursor в середине смены владельца.** Блог о приобретении и тарифы — first-party, но продукт теперь продаётся через The X Subscription. Это влияет на цены и маршрутизацию моделей, но не на runtime-механики.
- **У JetBrains три пересекающихся продукта.** AI Assistant, Junie и Air документированы раздельно; часть утверждений относится только к одному из них. В каждом пункте JetBrains продукт назван явно.
- **Независимой проверки нет.** Ни один бенчмарк не воспроизведён, ни один агент не установлен, ни один тариф не куплен. Заявления вендоров помечены как claim. Страница, где фича не описана, трактуется как «не задокументирована на проверенных страницах», а не как «отсутствует».

### 3.2. Cursor

**Архитектура.** Cursor описывает агента как три компонента — "Instructions", "Tools" и "Model" — и утверждает, что настраивает инструкции и инструменты под каждую frontier-модель (C2). Поверхности: редактор, Agents Window, CLI `agent`, Cloud Agents, iOS-приложение и web (C21). Компания приобретена SpaceX 2026-08-14 и продаётся через The X Subscription (C22, C15).

**Agent loop.** «There is no limit on the number of tool calls Agent can make during a task» (C2). Queued messages ждут завершения текущей задачи; `Cmd+Enter` отправляет сразу; steering доставляется «at the agent's next tool call» (C2). Checkpoints — автоматические снапшоты перед значимыми изменениями; восстановление «reverts files only; it does not remove messages from the conversation», хранятся локально и отдельно от Git (C2). Plan Mode задаёт уточняющие вопросы, исследует кодовую базу, создаёт редактируемый план и сохраняет его по умолчанию в домашней директории с опцией "Save to workspace" (C3). Для крупной работы используется "Project", где «a coordinator agent plans the work and delegates it to other agents» (C2).

**Инструменты.** Search files and folders, web, fetch rules, read files, edit files, run shell commands, browser, image generation, ask questions (C2). Browser — нативный инструмент: логи браузера «are written to files that Agent can grep and selectively read», скриншоты идут через file-reading tool «as images rather than relying on text descriptions», агент определяет запущенные dev-серверы и порты (C7).

**Стратегия контекста.** Cursor явно отказывается от upload-based embedding-индекса для поиска: Instant Grep «builds and queries its index on your machine», поддерживает full regex и word-boundary и «does not upload file paths or code to build a search index»; «it does not store embeddings of your codebase for search» (C5). Содержимое файла всё равно может попасть в запрос к модели, когда агент открывает совпадение (C5). Rules — `.cursor/rules/*.mdc`; обычный `.md` «is ignored by the rules system because it has no frontmatter» (C4). Четыре категории (Project, User, Team, AGENTS.md) и четыре режима применения (Always Apply, Apply Intelligently, Apply to Specific Files, Apply Manually); приоритет Team → Project → User, все применимые правила сливаются, вложенные `AGENTS.md` комбинируются с приоритетом более специфичного, рекомендация — держать правила под 500 строк (C4). Субагент Explore существует потому, что исследование кода «generates large intermediate output that would bloat the main context» (C11).

**Разрешения / sandbox.** Три пользовательских Run Modes (C8):
- **Auto-review** — allowlisted-вызовы выполняются сразу, остальные shell-команды по возможности идут в sandbox, прочее уходит классификатору, который работает на бэкенде Cursor; документация прямо говорит: «Auto-review is not a security boundary», потому что «The classifier can make mistakes».
- **Allowlist** — без approval выполняются только allowlisted-действия, sandbox опционален.
- **Run Everything** — без sandbox и классификатора.

`permissions.json` управляет тем, что Auto-review запускает автоматически; `sandbox.json` задаёт сетевые домены и дополнительные читаемые/записываемые пути; проектные файлы перекрывают пользовательские, а team policy лежит сверху, поэтому «local files cannot weaken those protections» (C8). Доступ по умолчанию — чтение/запись внутри workspace; защищённые пути включают `.git/config`, `.git/hooks`, `.vscode`, `.cursorignore`; сеть «Blocked by default, then opened by your network mode»; чтение по умолчанию — `System`, то есть агент «can read files outside the workspace without approval» (C8). MCP-инструменты подчиняются тем же Run Modes, approval по умолчанию требуется, enterprise allowlists ограничивают автоматический запуск инструментов (C9). Cloud Agents дополнительно используют per-agent Firecracker microVM в отдельном AWS-аккаунте, TLS 1.2+, AES-256 с ключами на агента и CMEK для Enterprise (C19).

**Расширяемость.** Hooks дают 18 agent-событий (`sessionStart`, `sessionEnd`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `subagentStart`, `subagentStop`, `beforeShellExecution`, `afterShellExecution`, `beforeMCPExecution`, `afterMCPExecution`, `beforeReadFile`, `afterFileEdit`, `beforeSubmitPrompt`, `preCompact`, `stop`, `afterAgentResponse`, `afterAgentThought`), два Tab-события и `workspaceOpen`; типы — command и LLM-evaluated prompt; источники сливаются Enterprise → Team → Project → User, запускаются все совпавшие hooks, deny > ask > allow (C10). По умолчанию сбой «fail-open»; `failClosed: true` включается отдельно, и документация рекомендует его для `beforeMCPExecution` (C10). Cloud agents запускают только command hooks, не видят user-level hooks, а для HTTP MCP вызовов Cursor «ignores `updated_input`» и редактирует вывод `postToolUse` (C10) — это задокументированная асимметрия, а не баг-репорт. Plugins объединяют rules, skills, agents, commands, MCP servers и hooks; есть Cursor Marketplace и team marketplaces с режимами Default Off/On/Required (C21).

**Субагенты / оркестрация.** У каждого субагента свой context window; foreground блокируется до завершения, background возвращает управление сразу; несколько субагентов могут работать параллельно; prompt, tools и model настраиваются (C11). Субагенты стартуют с чистым контекстом и не видят историю разговора, поэтому родитель должен передать нужный контекст (C11). Встроенные субагенты — **Explore** (много параллельных поисков на быстрой модели) и **Browser** (фильтрует шумные DOM-снапшоты) (C11). Projects добавляют слой координатора (C2).

**Маршрутизация моделей.** Auto разделён на Cost, Balance и Intelligence через Cursor Router; на individual-тарифах доступен только Cost; Teams/Enterprise могут включить Router, причём в Enterprise он изначально выключен и требует opt-in (C15). Plus ограничен Cursor-моделями на фиксированных настройках и исключает Auto, Cloud Agents, Automations, Bugbot и сторонние модели (C15). Composer 2.5 — собственная агентная модель Cursor в недельном пуле Cursor-моделей (C24). BYOK покрывает OpenAI, Anthropic, Google, Azure и AWS Bedrock; на Teams/Enterprise Cursor Token Rate всё равно применяется к моделям, где он предусмотрен (C23).

**Контроль затрат / лимиты.** Тарифы: Free $0, Plus $8, Premium $30, Super $100, Ultra $200; Teams $30+/место; Enterprise custom; на каждом платном тарифе есть «a pool of AI usage shared across Cursor and Grok», обновляемый еженедельно, с top-offs при исчерпании (C14). Пользователи сторонних моделей могут ставить spending caps; в Enterprise есть granular spend controls и лимиты на группы (C14). Cloud Agents требуют Premium и выше, Teams, Enterprise или legacy paid plan — «Free and Plus don't include them» — и spend limit запрашивается при первом использовании (C6). Bugbot перешёл на usage-based billing; средний запуск «$1.00 and $1.50», есть уровни effort Low/Default/High/Smart (C26).

**UX.** Agents Window — agent-first поверхность с multi-workspace и параллельными агентами; changelog добавляет Voice Chat (6 ноя 2026), Build Live Apps (5 ноя), Agent SDK (20 окт), Cloud Agent Canvases + Environments API с до 300 репозиториев (16 окт) и Origin App Marketplace (13 окт) (C21).

**Ревью.** Agent Review запускает отдельное ревью локальных изменений, может работать автоматически после каждого коммита или вручную через `/agent-review` либо Source Control tab, поддерживает глубину Quick/Deep и читает правила из `BUGBOT.md`; начиная с Cursor 3.11 настройка переезжает в Git & PRs > Pull Requests (C12). Bugbot отдельно ревьюит PR-диффы, пропускает слишком большие PR, игнорирует `linguist-generated` и публикует CI-статусы `success`/`neutral`/`failure` (C27, C14).

**Телеметрия / evals.** OTel Export — только Enterprise: OTLP/HTTP protobuf на `/v1/metrics` и `/v1/logs`, метрики (tokens, tool calls, best-effort cost) и логи (API requests, errors, corrections, skills, hooks, plugins, cloud-agent lifecycle); содержимое диалога и MCP tool I/O включаются opt-in, экспорт идёт server-side (C18). Evals — часть Agent SDK, и changelog называет их одной из ключевых возможностей (C21); точный API eval-файлов находится на страницах SDK reference и в этой ветке не перезапрашивался.

**Enterprise.** SSO, SCIM, RBAC, MDM, organization groups, model access control как team baseline плюс most-permissive union с группами, ограничение BYOK, audit logs, CMEK, private connectivity, self-hosted cloud-agent machines (C13, C16–C19). Privacy Mode гарантирует, что код не используется для обучения, и может быть включён обязательным для всей команды (C25); Cloud Agents — «the only feature that requires Cursor to store code», зашифрованные копии удаляются после запуска (C17). Несколько моделей Claude Fable требуют provider-side retention, и запросы «fail until the model's data retention policy is approved» (C17).

**Ценообразование.** Подписка с общим недельным пулом usage плюс отдельно оплачиваемое Grok API usage (C14, C15).

**Замеченные слабости документации.** Лендинг `cursor.com/docs` — каталог моделей, а не описание архитектуры (C1). Семантика внутреннего compaction на проверенных страницах не описана. Страница rules документирует молчаливое игнорирование `.md`, но не описывает диагностику в UI (C4). Классификатор Auto-review описан как ошибающийся, при этом является дефолтом (C8).

### 3.3. Windsurf / Devin Desktop

**Архитектура.** `windsurf.com` теперь 308-редиректит на `https://devin.ai/desktop`, а документация говорит: «Devin Desktop is the new name for Windsurf», Agent Command Center «front and center» (W1); индекс документации — 96 desktop-страниц плюс отдельные деревья CLI, enterprise и API (W2). Devin Local — «our next-generation agent harness shared with Devin CLI», который «operates on your machine with access to your local files, tools, and environment» (W3). Cascade явно legacy: «Devin Desktop no longer starts new Cascade conversations and no longer opens old ones» (W10). ACP позволяет редактору хостить сторонних агентов (W13).

**Agent loop.** Пять режимов Devin Local — Code, Smart, Ask, Plan, Bypass Permissions (W4):
- **Code** авто-одобряет правки внутри workspace; shell-команды, web fetches и MCP-инструменты требуют approval, если нет allow-правила.
- **Smart** сохраняет авто-одобрение правок и добавляет «a fast model that decides, for every other action, whether it is safe to run without asking»; высокорисковые категории (установка пакетов, мутирующий git, `rm`, `sudo`, деструктивные cloud CLI, чувствительные файлы) всегда спрашивают.
- **Ask** — read-only; **Plan** исследует read-only и пишет план на утверждение; **Bypass** авто-одобряет всё, если org-политика не требует approval.
- Deny- и ask-правила, заданные админом, побеждают «even in Bypass Permissions» (W4).

Legacy Cascade имел документированный дефолт 40 инвокаций на промпт, причём `continue` считался новым prompt credit, revert был «currently irreversible», а параллельные Cascade при правке одного файла «can race» (W10).

**Инструменты.** Terminal с Command mode (`Cmd/Ctrl+I`), отправка выделения агенту (`Cmd/Ctrl+L`), @-упоминание активных терминалов, previews, MCP и retrieval Fast Context (W6, W8).

**Стратегия контекста.** Контекстный движок RAG-based: индексируется «the entire local codebase (including files that are not open)» и релевантные сниппеты подтягиваются при письме, вопросах и вызове команд; Pro получает расширенные context/index limits, Teams/Enterprise могут индексировать удалённые репозитории, а enterprises могут использовать полный fine-tuning в сочетании с RAG (W7). Fast Context — «a specialized subagent» на SWE-grep и SWE-grep-mini, заявлено «up to 20x faster», до «8 parallel tool calls per turn over a maximum of 4 turns» с ограниченным набором grep/read/glob (W8). Cascade Memories автоматически генерируются в рамках workspace, извлекаются по релевантности, не переносятся между workspace, и «Creating and using auto-generated memories do NOT consume credits» (W9).

**Разрешения / sandbox.** Правила allow/ask/deny, где «Deny rules block actions entirely (highest priority)» (W5). Охват — «file reads, file writes, command execution, HTTP fetches, and MCP tools» на уровнях project, user или organization; карточки approval позволяют отредактировать команду, выбрать approve/always-allow/reject и «Session-wide grants», которые покрывают и субагентов (W5). MCP-инструменты по умолчанию спрашивают; админы могут default-allow доверенные серверы или инструменты (W5). Флаг `--sandbox` включает OS-level изоляцию: writable-пути выводятся из выданных `Write(...)` scopes плюс workspace, readable — всё, кроме путей из `Read(...)` deny, а выданные посреди сессии `Write` расширяют sandbox для последующих команд; при невозможности включить sandbox «the CLI will **refuse to start** rather than running unsandboxed» (W23). Windows не поддерживает OS-sandbox и жёстко падает; Linux требует `bubblewrap` и `socat`; сетевой фильтр прямо назван «currently unstable» (W23).

**Расширяемость.** Кастомизации Devin Local — rules, skills, plugins, MCP servers и hooks; документация подчёркивает, что «every customization uses the Devin CLI format and discovery, and a customization you write for one works in the other» (W22). `AGENTS.md`, `AGENTS.local.md` и `AGENT.md` читаются как always-on rules в корне workspace и в каждой директории между корнем и рабочей директорией (W22). Cascade MCP поддерживает `stdio`, `Streamable HTTP` и `SSE`, OAuth для удалённых серверов, конфиг в `~/.config/devin/mcp_config.json`; enterprise-пользователи должны включить его вручную (W11). Legacy Cascade Workflows — markdown-файлы в `.windsurf/workflows/`, вызов slash-командой, последовательные шаги, могут вызывать другие workflows; Devin Local их не поддерживает и рекомендует миграцию в skills (W12, W10). Заметная механика миграции: Devin CLI автоматически импортирует rules и конфигурацию из Cursor, Windsurf, Claude Code, GitHub Copilot, Codex, Kiro, OpenCode и Zed (W24).

**Субагенты / оркестрация.** Devin Local «can spawn independent subagents to handle subtasks — either in the foreground or background»; они «share tools and codebase context with the parent agent but operate in their own conversation chain» (W3). Agent Command Center управляет локальными и облачными сессиями в одном представлении, умеет duplicate session, @-mention правил, редактируемые queued messages и блокировку сессий во время работы (W14). Маркетинговая страница добавляет «agent swarms», координируемые Devin, «each producing its own PRs» (W1, claim).

**Маршрутизация моделей.** Два документированных роутера: **Adaptive**, который «evaluates each request and dynamically chooses the right underlying model» (простое→быстрое, сложное→мощное) и по умолчанию выключен в enterprise до включения админом (W16); и **Fusion**, который объединяет frontier-**lead** (планирует, рассуждает, ревьюит) с дешёвым **sidekick** (пишет код, запускает сборки и тесты), с настраиваемыми lead, effort, sidekick и Fast Mode; Fusion доступен только на платных тарифах, не в free/trial (W17). Ставки моделей опубликованы «as of November 9, 2026» (W15).

**Контроль затрат / лимиты.** Devin Desktop перешёл на квоты в марте 2026: «a daily and weekly usage allowance that refreshes automatically», учёт token-based, бесплатные модели не считаются, дневной объём «more than 1/7 of your weekly quota», extra usage «billed at API list prices» (W19). «Quota limits never limit your extra usage, just the built-in allowance from your plan» (W19). Тарифы: Free $0, Pro $20, Max $200, Teams «$80/month for team plan + $40/mo per full dev seat», Enterprise custom; конкурентность — «Up to 10» для Free/Pro и без лимита для Max/Teams, числовые квоты не раскрыты (W20). Новые Teams-тарифы исключают SSO, который стал «an Enterprise-only feature» (W19).

**UX.** Agent Command Center со Spaces, Kanban и multi-agent management (W1); одно нативное OS-уведомление на сессию для Devin Local и ACP-агентов (W14); база VS Code 1.141.2 / Electron 43.8.3 (W25).

**Телеметрия / evals.** Индекс документации содержит Analytics API v2 для «consumption, active users, agent output, and tool calls with Bearer-token authentication, grouping, and pagination» (W26). OTel-страница на проверенных путях не найдена.

**Развёртывание / enterprise.** Три поверхности принуждения: team settings, доставляемые со статусом аккаунта, MDM device policies, применяемые до входа, и system-level files для каждого workspace (W21). Devin Local Agent «gated off by default on Enterprise plans»; админы могут разрешать/запрещать облачную делегацию, CLI plugins и Quick Review (W21). Quick Review запускает вторичного агента по локальным изменениям: SWE-check бесплатен, GPT-5.5/Opus 4.7 ревью тарифицируются по токенам (W18).

**Ценообразование.** Free/Pro/Max/Teams/Enterprise с квотами и extra usage по API-ценам (W19, W20).

**Замеченные слабости документации.** Ребрендинг оставил двойной словарь: «Windsurf» и «Devin Desktop» обозначают один продукт в админской документации (W21), пути лендинга всё ещё содержат `windsurf` (W13), а Cascade одновременно «legacy» и подробно документирован (W10). Старый enterprise-URL после редиректа отдаёт 404 (§8.3). Квоты описаны качественно («Light», «Increased», «Significantly higher»), тогда как overage priced точно (W20).

### 3.4. GitHub Copilot

**Архитектура.** Cloud agent состоит из «the client, the session, and the environment»; сессии «can be shared and resumed across clients» (G1). Среды — cloud sandbox, GitHub Actions или remote/self-hosted; cloud — дефолт там, где выбор предлагается; cloud-сессии «can span across repositories in one organization», Actions-сессии ограничены одним репозиторием (G1). Локальный agent mode — collaborative IDE-опыт, cloud agent — асинхронный, automations запускаются событиями или расписанием (G4).

**Agent loop.** Документированный цикл: «plan a task, use tools to take action, inspect the results, and adjust its approach» (G4). Plan mode в CLI «analyzes your request, asks clarifying questions ... and builds a plan before writing any code» (G2). `/fleet` позволяет главному агенту решить, можно ли разбить промпт, стать orchestrator и запустить субагентов параллельно (G5). Таксономия автономности явная: collaborative (направлять и одобрять), asynchronous (делегировать и позже ревьюить) и automated (событие или расписание запускает агента), при этом пользователь остаётся «responsible for defining the goal and constraints, granting appropriate access, and reviewing the agent's work» (G4).

**Инструменты.** Встроенные file read/edit, search, shell, MCP-инструменты, skills и hooks (G2, G7, G8, G9). MCP работает «across all major Copilot surfaces» и ограничен «up to 50 MCP servers in total across personal and repository-level configurations», секреты с префиксом `COPILOT_MCP_` (G7).

**Стратегия контекста.** Индексация репозитория семантическая и автоматическая: при старте repo-scoped чата репозиторий индексируется, «initial indexing can take up to 60 seconds for a large repository», последующие обновления обычно отражаются «within seconds», и «There is no limit to how many repositories you can index» (G11). Custom instructions поддерживают `.github/copilot-instructions.md`, path-specific `.github/instructions/NAME.instructions.md` с `applyTo`, `AGENTS.md` в любом месте с приоритетом ближайшего и один корневой `CLAUDE.md`/`GEMINI.md` (G18). Content exclusion заставляет Copilot игнорировать файлы, но документация прямо говорит, что это «is not a filesystem security boundary» и «not guaranteed to be respected by third-party MCP servers or clients», а symlinks и remote filesystems не покрываются (G12).

**Разрешения / sandbox.** Локальный sandbox запускает shell-команды и встроенный поиск как sandboxed child processes под «deny-by-default» filesystem policy; локальные MCP и LSP по умолчанию работают внутри sandbox; встроенные file read/edit инструменты проверяют ту же политику «in software», потому что OS-sandbox их не видит; удалённые MCP-серверы вне filesystem policy; поведение субагента зависит от инструмента, который он вызывает (G20). Content exclusion явно назван guardrail, а не security boundary (G12). CLI approvals: Yes / Yes-and-approve-tool-for-session / No-with-instruction; `--deny-tool` «takes precedence over the `--allow-all-tools` and `--allow-tool` options»; документация признаёт «Scoping of permissions is heuristic» (G2). Безопасность cloud agent добавляет ограничение «one branch / one PR per task» и отмечает, что branch protection может помешать Copilot создавать PR, если админ не разрешит bypass (G1).

**Расширяемость.** Custom agents — Markdown + YAML frontmatter с ограничением инструментов и опциональными MCP-серверами, на уровнях repository, organization, enterprise плюс личные профили в CLI; встроенные агенты — `explore`, `task`, `general-purpose`, `code-review`, `research`, `rubber-duck`, `security-review` (G6). Agent skills следуют открытому стандарту Agent Skills и лежат в `.github/skills`, `.claude/skills` или `.agents/skills` (проект) и `~/.copilot/skills` или `~/.agents/skills` (личные); `gh skill` умеет их устанавливать (G8). Hooks запускают shell-команды в точках session/prompt/tool с JSON на входе, в `.github/hooks/*.json` и `~/.copilot/hooks/*.json`, с подмножеством в облаке (G9).

**Субагенты / оркестрация.** Custom agent — «a definition of a specialist»; «A subagent is an agent doing delegated work in a separate context window»; независимые задачи могут идти параллельно; «repository instructions are included for the session agent but are not included for a custom subagent by default» (G6). `/fleet` делает главного агента orchestrator и может расходовать больше AI credits (G5).

**Маршрутизация моделей.** Мультивендорный набор моделей (G13) плюс Fusion-маршрутизация, анонсированная в changelog (G19); BYOK custom providers настраиваются в CLI (G2).

**Контроль затрат / лимиты.** Все тарифы используют GitHub AI Credits: Pro $10/мес с 1 500 кредитов суммарно, Pro+ $39 с 7 000, Max $100 с 20 000, Business $19/место с 1 900, Enterprise $39/место с 3 900; Copilot access — $0 для лицензиатов GitHub Enterprise Cloud или $10 standalone без включённого allowance; Copilot in the cloud не входит в Free (G13). Rate limits «temporary», документированные remedies — подождать, проверить usage, апгрейдить план или задать бюджет на additional usage (G14). У cloud agent есть жёсткие операционные лимиты: Actions-сессии максимум 59 минут, «only work on one branch at a time», «one pull request per task», только GitHub-репозитории (G1).

**UX.** Agents tab/panel на GitHub.com, входные точки через issue и PR, `/fleet`, интерактивный и программный режимы CLI, plan mode по Shift+Tab (G4, G5, G2).

**Телеметрия / evals.** OTel отправляет traces (поток сессии, вызовы модели, tool use), metrics (расход токенов) и events (принят/отклонён edit); по умолчанию нет прямо идентифицирующих атрибутов, промптов, ответов, аргументов/результатов инструментов и сырых policy details, а админы могут независимо включать capture classes (identity, prompts, responses, tool arguments, tool output, policy detail); fine-grained capture поддержан в CLI, Copilot app и VS Code Agent Host (G15). Usage metrics API и impact dashboard поставляются через changelog (G19).

**Развёртывание / enterprise.** Policies управляют «which GitHub Copilot features, agents, and models your users can access»; две отдельные policy определяют, включены ли неконфигурированные GA-фичи/модели по умолчанию; audit log отслеживает изменения policy (G17). У MCP есть enterprise policy, выключенная по умолчанию и действующая только для Business/Enterprise seats; рекомендуемый механизм allowlist — `managed-settings.json`, тогда как custom registry — «weaker enforcement», потому что matching идёт только по имени или ID и «Users can bypass the restriction by editing configuration files» (G16). Cloud custom environments используют `.github/workflows/copilot-setup-steps.yml` с единственным job `copilot-setup-steps`, который должен быть на default branch; кастомизировать можно только `steps`, `permissions`, `runs-on`, `services`, `snapshot` и `timeout-minutes` (максимум 59); файл не применяется к cloud sandbox-сессиям; встроенный firewall несовместим с self-hosted runners и Windows (G3).

**Ценообразование.** Per-seat подписка + AI credits (G13). Copilot code review доступен на всех платных тарифах и может быть расширен на участников без лицензии через две policy, одна из которых разрешает AI-credit paid usage (G10).

**Замеченные слабости документации.** Документация Copilot Workspace отдаёт 404 на обоих проверенных путях (G21, G22; §8.3); «Workspace» следует считать недокументированным, а не поставленным. Детали стоимости code review находятся на странице, чьё тело не извлеклось (§8.3), поэтому цена ревью за запуск неизвестна. Лимит параллельности cloud agent на проверенных страницах не указан (G1).

### 3.5. JetBrains AI (AI Assistant, Junie, Air)

**Архитектура.** JetBrains сейчас поставляет три пересекающихся слоя: AI Assistant (IDE-плагин с чатом и coding agents), Junie (собственный coding agent с CLI, IDE-плагином, GitHub Action и GitLab CI) и Air (хост агентов в JetBrains IDEs, web, CLI и mobile) (J1, J18, J19). AI Assistant «integrates the following coding agents»: Junie, Claude Agent, Codex, GitHub Copilot плюс внешние агенты через ACP (J2). Air позиционируется как «one system for building software with agents» и подключает Claude Agent, Codex, Junie, Copilot, OpenCode и «any you can connect via ACP» (J19, claim). Air in JetBrains IDEs стал GA с релизом 2026.3 (J21).

**Agent loop.** Документированный паттерн: выбрать агента, выбрать operation mode и модель, добавить instructions/skills/MCP, написать промпт, «Authorize actions — approve, deny, or let them run automatically based on the agent's operation mode», затем отревьюить результат и оставить или откатить (J2). У каждого агента свои режимы: Junie — Brave и Debug; Claude Agent — Auto, Default, Accept Edits, Plan, Don't Ask, Bypass; Codex — Read-only, Agent, Agent (full access); Copilot — Agent, Plan, Autopilot (J2). Junie CLI добавляет Plan mode: read-only исследование, живой design document, plan view с вкладками Requirements/Technical design/Testing/Delivery steps и явные действия Confirm/View/Open/Save-and-stop; Plan mode действует только на следующий промпт (J12). Cloud agents провижнят среду, чекаутят репозиторий, запускают агента, пушат task branch и оставляют ревью/мерж пользователю (J5).

**Инструменты.** Отличительная механика JetBrains — IDE-нативный инструментарий, отданный агентам: «Through the IDE's MCP server and built-in skills, agents can check inspections, run your build and run configurations, query your databases, and use the IDE's own refactorings. In IntelliJ IDEA and CLion, they can also drive the debugger» (J21). Сам AI Assistant также даёт completion, next-edit suggestions, refactoring suggestions, генерацию тестов/документации, commit messages, PR descriptions, разрешение конфликтов и объяснение query plans (J1).

**Стратегия контекста.** AI Assistant отправляет «the currently open file, selected code, or recent changes» (J1). Project rules лежат в `.aiassistant/rules/*.md` с типами Always, Manually, By model decision, By file patterns и Off и применяются к chat mode (J8). Агенты используют `AGENTS.md` (Junie, Codex, Copilot) или `CLAUDE.md` (Claude Agent) как instructions; только Junie уважает `.aiignore` по таблице сравнения (J2). Junie CLI ищет guidelines в строгом порядке: сначала `.junie/AGENTS.md`; иначе корневой `AGENTS.md` плюс `.junie/playbook.md` и `.junie/rules/*.md`; иначе legacy `.junie/guidelines.md` или папка; глобальный `~/.junie/AGENTS.md` сливается, но project-level побеждает, а идентичное содержимое дедуплицируется (J16). Air добавляет «Air Context» semantic indexing, заявленный как ускорение выполнения и снижение стоимости за счёт меньшего сканирования кодовой базы (J19, claim). Инженерный блог JetBrains описывает Air Context как production RAG-систему для поиска по коду (J21).

**Разрешения / sandbox.** Авторизация — на агента и на режим (J2). Junie CLI спрашивает approval для «most of the terminal commands, editing files outside the project, or invoking MCP tools»; «Always allow» пишется в `~/.junie/allowlist.json`; Brave mode имеет уровни, переключаемые `/brave` или Ctrl+B (J11). Hooks Junie включают `PermissionRequest`, который может «automatically allow or deny sensitive action permission requests without manual confirmation» (J14). Единой OS-level sandbox-страницы для AI Assistant/Junie на проверенных путях не найдено; не следует выводить её существование.

**Расширяемость.** ACP — основа интероперабельности: AI Assistant устанавливает курируемые агенты из реестра, управляемого в настройках (install/update/uninstall с пробросом custom MCP servers и IntelliJ MCP server) (J22), или кастомный `~/.jetbrains/acp.json`, автоматически скачивает Node/Python runtime, пробрасывает custom MCP и IntelliJ MCP server, не требует подписки JetBrains AI для ACP-агентов; ACP-агенты не поддерживаются в WSL (J4). MCP поддерживает STDIO, Streamable HTTP и legacy SSE, JSON-конфиг, импорт из Claude Desktop, global/project level и auto-enable (J6). Skills поддерживаются только Claude Agent и Codex внутри AI Assistant, импортируются из `~/.codex/skills` или `~/.claude/skills` и ставятся на уровне IDE, проекта, Codex или Claude Agent (J7). Junie добавляет custom subagents (J13), hooks (J14), MCP с installation assistant и дефолтным таймаутом 60 секунд (J15) и `~/.junie/allowlist.json` (J11).

**Субагенты / оркестрация.** Junie CLI делегирует автоматически, когда задача совпадает с name/description субагента; субагенты работают в своём контексте и возвращают результат; фича в EAP; политика моделей — `SameModelOnly` (субагенты могут параллелиться только на той же модели) или `Auto` (дефолт; может брать более дешёвые capable tiers, если это не замедляет сессию); файлы субагентов — Markdown + YAML в `.junie/agents/` или `.agents/` (проект) и те же пути в домашней директории, с полями `tools`, `disallowedTools`, `mcpServers`, `model`, `reasoningLevel`, `maxTurns`, `skills`, `allowPromptArgument`; Junie также автоимпортирует `.cursor/agents/`, `.claude/agents/` и `.codex/agents/` (J13). Кросс-инструментальный импорт — повторяющийся паттерн JetBrains: skills, subagents и MCP-конфиги импортируются, а не пересоздаются (J7, J13, J6). Air добавляет параллельные сессии с отдельными Git worktrees и уведомления (J21).

**Маршрутизация моделей.** AI Assistant по умолчанию использует JetBrains AI service, поддерживает BYOK через Providers & API keys и локальные модели через Ollama и LM Studio; «Not all features may be available when using models from third-party providers» (J9). Air позволяет «Bring your existing provider subscription or API keys, or even base URL» и «Switch between subscriptions – even mid-session»; организации могут один раз добавить ключи Amazon Bedrock, OpenAI, Anthropic или другого провайдера для всех разработчиков (J19, claim). Junie CLI поддерживает аккаунт JetBrains, Junie API key, BYOK из OpenAI/Anthropic/Google/xAI/OpenRouter/GitHub Copilot и кастомные endpoints вроде LiteLLM, Ollama и LM Studio (J11). Маркетинг Junie заявляет «Plan on a powerful model, implement on a fast one» (J20, claim), что согласуется с документированным разделением plan/implementation (J12), но остаётся маркетинговым утверждением.

**Контроль затрат / лимиты.** Тарифы AI Assistant: AI Free 3 кредита/30 дней; для individual — AI Pro $10 с 10 кредитами и AI Ultimate $30 с 35 кредитами; для организаций — AI Pro $20 с 20 кредитами, AI Ultimate $60 с 70 кредитами и AI Enterprise $60 с квотой на уровне AI Ultimate или выше; один AI credit равен $1, купленные кредиты действуют 12 месяцев; организации, мигрировавшие в JetBrains Central, используют общий пул с лимитами на пользователя (J10). Junie Lite — постоянный бесплатный тариф (сейчас Qwen 3.6 27B) без опубликованной квоты и без лимита tool calls, инференс «exclusively on JetBrains infrastructure», данные не передаются провайдеру модели (J17). Маркетинг Junie указывает другие цены — Lite бесплатно, AI Pro $8.33, AI Ultimate $25 — что расходится с licensing-страницей ($10/$30) (J20 vs J10); страницу документации следует считать авторитетной, а маркетинговую — устаревшей или годовым/скидочным расчётом (вывод, не подтверждено).

**UX.** AI Chat agent picker объединяет агентов в одном tool window (J2); Junie CLI имеет live follow-ups, `@`-ссылки на файлы, ввод изображений, поиск по истории промптов, `!`-префикс для shell и plan view (J11, J12); Air добавляет параллельные сессии, worktrees, presets и уведомления (J21).

**Телеметрия / evals.** AI Assistant выполняет «opt-in collection of detailed data about AI feature usage, including the full communication between you and the LLM (both text and code fragments)», выключенную по умолчанию, используемую для улучшения продукта и обучения, никогда не передаваемую наружу; пользователи могут открыть `ai-assistant-requests.md` и посмотреть, что было отправлено (J3). Публичного каталога метрик/событий или OTel-экспорта для AI Assistant/Junie на проверенных страницах не найдено. Air Governance заявляет аналитику «what that usage costs and delivers» (J19, claim).

**Развёртывание / enterprise.** Организации на JetBrains IDE Services или JetBrains Central управляют тем, какие ACP-агенты доступны и можно ли добавлять свои; реестр может быть ограничен, кастомные агенты заблокированы (J4). Cloud agents «available only to organizations that have been migrated to JetBrains Central» и работают на Air (J5). Air Teams предлагает выделенные cloud-среды на проект с контролем VM size, интернет-доступа, переменных и секретов (J19, claim). Air Governance анонсирован как управление «which AI agents, models, and providers your teams use», лимитами расходов и отчётностью (J19). Цены AI Assistant/Air в серверном HTML отсутствуют — `jetbrains.com/ai-ides/buy/` вернул только заголовок и ссылку "Store" (J23), поэтому цены AI Assistant/Air здесь не утверждаются.

**Ценообразование.** Кредитные тарифы на пользователя с бесплатным уровнем; Junie Lite бесплатен постоянно; Enterprise custom (J10, J17).

**Замеченные слабости документации.** Три продукта с пересекающимся охватом и без единого контракта «что выбрать»; субагенты и hooks Junie CLI помечены EAP (J13, J14); таблица AI Assistant показывает `—` для skills у Junie, тогда как документация Junie заявляет поддержку skills через `.agents` (J2 vs J13) — как минимум несоответствие информационной архитектуры; цены расходятся между docs и marketing (J10 vs J20); цены AI Assistant/Air отсутствуют в HTML (J23).

### 3.6. Zed AI

**Архитектура.** Zed — open-source редактор: README гласит «Zed source code is licensed primarily under GPL-3.0-or-later, with Apache-2.0 components where marked» (Z18), GitHub API показывает 94 721 звезду и последний push 2026-11-11 (Z19). AI организован вокруг трёх путей агента — Zed Agent, External Agents через ACP и Terminal Threads (Z1, Z8). Внешние агенты «run as separate processes that communicate with Zed over ACP»; «Zed hosts the thread», а внешний агент «usually owns its own runtime, auth, model selection, tools, and native configuration» (Z8). Сам ACP — Apache-2.0-репозиторий, описанный как «A protocol for connecting any editor to any agent» (Z20).

**Agent loop.** Agent Panel — место, где пользователи «prompt agents, add context, review changes, and manage active threads»; ответы стримятся с индикаторами используемых инструментов; часть фич зависит от интеграции агента (Z6). Parallel Agents запускают «multiple threads across projects and worktrees», каждый со своим агентом, context window и историей (Z7). Пошаговый цикл и политика compaction на проверенных страницах не документированы; настройка `agent.compaction_model` подразумевает автоматическое сжатие, но триггер в полученном фрагменте не описан (Z17).

**Инструменты.** Шестнадцать инструментов: `diagnostics`, `fetch`, `find_path`, `grep`, `list_directory`, `read_file`, `search_web`, `copy_path`, `create_directory`, `delete_path`, `edit_file`, `move_path`, `write_file`, `terminal`, `skill`, `spawn_agent`; точный список «can vary by Agent Profile, selected model provider, and Zed version»; `search_web` «only available to Zed Pro subscribers using the Zed provider»; `terminal` создаёт «a new shell process for each invocation»; `spawn_agent` делегирует субагенту с собственным context window (Z2).

**Стратегия контекста.** Zed не документирует семантический индекс кодовой базы; retrieval — `grep`/`find_path`/`list_directory` плюс явно приложенный контекст (Z2). Agent Profiles выбирают доступные built-in и MCP-инструменты и модель по умолчанию, но «Profiles do not decide whether a tool call is allowed automatically» (Z4). Skills — папки с `SKILL.md`, показываются как каталог и загружаются по требованию, с `/create-skill` и импортом из реестра skills.sh (Z10). Instructions и project-local skills загружаются только из доверенных worktree (Z13).

**Разрешения / sandbox.** `agent.tool_permissions` поддерживает `allow`/`deny`/`confirm` с массивами `always_allow`, `always_deny`, `always_confirm` из правил `{pattern, case_sensitive}` на Rust regex; приоритет — built-in security rules > `always_deny` > `always_confirm` > `always_allow` > tool-specific default > global default (Z3). Жёсткие защиты применяются только к `terminal` и блокируют рекурсивное удаление корня ФС, домашней директории, текущей и родительской директорий; проверяются и сырая команда, и каждая разобранная подкоманда; «There are no other built-in rules» (Z3). OS-sandbox применяется только к `terminal` и `fetch`, но не к самому Zed, language servers, extensions, tasks, обычным вкладкам терминала, External Agents и Terminal Threads; на Linux нужен non-setuid `bwrap`, на Windows — WSL, и «sandboxes on Windows are weaker» (Z5). Доступ по умолчанию: terminal может читать большую часть ФС, писать внутри открытых проектных директорий, кроме `.git`; `.git` читается, но не пишется (Z5). `fetch` «governed by tool permissions, agent profiles, and project trust» и «not run inside the terminal OS sandbox» (Z2).

**Расширяемость.** MCP поддерживает Tools и Prompts, обрабатывает `notifications/tools/list_changed` и ведёт себя по-разному в зависимости от пути агента: Zed Agent использует настроенные в Zed серверы, External Agents могут получать их через ACP или читать нативный конфиг, Terminal Threads читают свой конфиг (Z9). MCP-серверы ставятся как extensions или добавляются как custom servers (Z9). Skills следуют конвенции папки `SKILL.md` с загрузкой по требованию и вызовом через slash (Z10). ACP — основная поверхность расширения сторонними агентами, а ACP Registry — «the primary way to install common External Agents» (Z8).

**Субагенты / оркестрация.** `spawn_agent` даёт субагенту собственный context window (Z2). Parallel Agents дают конкурентность на уровне threads, включая Terminal Threads и worktree isolation (Z7). Документированного orchestrator/scheduler уровня `/fleet` или Kiro workflows нет; External Agents хостятся, но не оркестрируются Zed (Z8).

**Маршрутизация моделей.** Пять путей доступа: Zed-hosted models, provider API keys, existing subscriptions, gateways (OpenRouter, Bedrock, Vercel и др.) и локальные модели (Z12). Обзор добавляет «choose a model access path», но логику router не описывает (Z1). Edit Prediction имеет отдельную настройку провайдера: по умолчанию Zeta, open-source модель, разработанная Zed, альтернативы — GitHub Copilot, Mercury Coder, Codestral и локальные/self-hosted модели (Z11).

**Контроль затрат / лимиты.** Personal — $0 «forever» с «Unlimited use with your API keys or external agents»; Pro — $10/мес с unlimited edit predictions, «$5 of tokens included», usage-based billing сверх этого по «API list price +10%» и 14-дневным триалом с $5 GPT-6 Luna usage; Business — «$30 per seat, per month» с org-wide model policies, data governance, unified spend visibility, unlimited edit predictions и RBAC, но «Business seats don't bundle a fixed LLM credit allotment» (Z15). Жёсткие rate limits не документированы.

**UX.** Agent Panel, Threads Sidebar с группировкой по проектам, agentic/classic layouts, worktree isolation и real-time multiplayer collaboration с channels, contacts, private calls, voice и доступом к файловой системе проекта (Z6, Z7, Z16).

**Телеметрия / evals.** Zed собирает анонимную клиентскую телеметрию и crash reports плюс серверную телеметрию для hosted AI/collaboration, которая «Required for these features to function»; пользователи могут отключать diagnostics и metrics; телеметрия отправляется каждые 5 минут или при накоплении 50 событий; клиентские метрики включают расширения файлов, использованные фичи, статистику проекта и обнаруженные фреймворки и «does not include your code or sensitive project details»; usage привязан к случайному telemetry ID, который при аутентификации «may be linked to your [account]» (Z14). Eval harness не найден.

**Развёртывание / enterprise.** Business добавляет org-wide AI model policies, data governance, spend visibility и RBAC; «SSO, SAML, and SCIM are planned but not currently available»; отдельного enterprise-тарифа нет, у Business нет бесплатного триала (Z15). AI privacy: по умолчанию нет retention; у Zed-hosted провайдеров есть no-training и zero-data-retention обязательства, кроме provider-designated safety-retention моделей вроде Anthropic Covered Models; provider API keys хранятся в системном keychain, а не в `settings.json`; edit prediction отправляет локальный контекст на каждое нажатие, а Zeta-запросы transient, если не включён сбор training data (Z13).

**Ценообразование.** Free/Pro/Business с usage-based hosted tokens и BYO keys (Z15).

**Замеченные слабости документации.** SSO/SCIM всё ещё «planned», хотя Business уже продаётся (Z15); OS-sandbox покрывает только два инструмента и явно не External Agents (Z5); отсутствие семантического индекса делает качество retrieval на больших репозиториях документированно неизвестным (Z2); release notes подтверждают работу над памятью и диском agent panel, а не над метриками корректности/eval (Z21).

### 3.7. Kiro

**Архитектура.** Kiro документирует единый agent harness на IDE, CLI, Web и Mobile: «The loop is the same everywhere» (K2). Работа организуется через specs, steering, hooks, custom agents, powers, skills и workflows (K1). Cloud sessions запускают «the Kiro agent harness in a managed cloud sandbox», сессия принадлежит аккаунту, а не приложению, и к ней можно подключиться с любой поверхности; в тариф включено до 10 одновременных cloud-сессий (K19).

**Agent loop.** Документированные шаги: «Context is assembled», «The model plans», «Every tool call is checked», «Tools execute», «Results feed back», «Context stays managed» (K2). Контекст включает промпт, разговор, steering-файлы и вложения; compaction суммирует старую историю (K2, K16). Workflows обобщают это в «graphs of agent steps, sequences, loops, and parallel branches», где каждый шаг идёт в собственной сессии со свежим контекстом, работает в фоне и может быть приостановлен/возобновлён/скорректирован (K20). Checkpoints восстанавливают файлы и контекст разговора; rewind форкает разговор, не трогая файлы (K17).

**Инструменты.** Единый harness даёт «File read/write, shell, web search/fetch, sub-agents, context, introspect» на всех поверхностях, «Hook creation and on-demand MCP tool loading» — только в IDE, «Background process» — тоже только в IDE (K18). Custom agents могут ограничивать дефолтный набор всех инструментов (K10).

**Стратегия контекста.** Steering — отличительная механика: workspace `.kiro/steering/`, global `~/.kiro/steering/`, foundation-файлы `product.md`, `tech.md`, `structure.md` и четыре режима включения — `always` (дефолт), `fileMatch`, `manual` (`#steering-file-name`) и `auto` (совпадение по description, также доступно как slash-команды); `AGENTS.md` всегда включаются и не поддерживают inclusion modes; workspace steering побеждает global при конфликте; team steering распространяется через MDM/Group Policy или центральный репозиторий; Web требует Configuration Sync, потому что cloud sandbox не читает локальный global steering (K6). Memory переносит между сессиями команды репозитория, конвенции, исправления, insights отладки, отвергнутые подходы и предпочтения (K15). Compaction автоматический, ручной `/compact` есть только в CLI, а индикатор использования контекста — на всех поверхностях (K16). Powers решают проблему перегрузки контекста: вместо загрузки всех MCP-инструментов они активируются по ключевым словам и грузят только нужные `plugin.json` + skills + `mcp.json`; документация приводит оценку, что пять MCP-серверов могут съесть «50,000+ tokens, 40% of your context window» до первого промпта (K12).

**Разрешения / sandbox.** Эффекты — `deny`, `ask`, `allow` и `evaluate` (слабейший, добавляется preset'ом approve-for-me); приоритет «deny > ask > allow > evaluate», и «A deny rule always wins regardless of scope» (K8). Правила поддерживают match patterns и опциональный список `exclude`; scope — user `~/.kiro/settings/permissions.yaml`, workspace `~/.kiro/workspace-roots/<hash>/permissions.yaml`, hardcoded invariants, enterprise policy, agent profiles и session rules; «There is no precedence between scopes - the most restrictive effect wins regardless of which scope it came from» (K8). Workspace-правила хранятся вне репозитория, поэтому «A cloned repo cannot inject permission rules» (K8). Hardcoded-правила запрещают запись в файлы разрешений и state stores Kiro и всегда спрашивают для `.git/**` и `.vscode/**`; недоверенный workspace спрашивает перед каждой shell-командой и не загружает custom agents, steering, MCP config и skills (K8). Shell-команды парсятся до matching, compound-команды делятся и каждая подкоманда оценивается отдельно, комбинированные короткие опции проверяются, опции, запускающие другую программу, «are never treated as read-only», команды, которые не удаётся разобрать достаточно хорошо, блокируются, а в non-interactive режиме «ask» превращается в «deny» (K8). Локальный command sandbox добавляет OS-границу «around shell commands run by Kiro's agent harness», при этом harness остаётся снаружи; он выключен по умолчанию и доступен в IDE 1.3+ и CLI 2.31+ local V3 sessions (K9).

**Расширяемость.** Custom agents — JSON или Markdown с идентичными полями, включая `tools`, `excludedTools`, `includeMcpJson`, `includePowers`, `resources` и permissions (K10). Skills следуют открытому Agent Skills standard с `.kiro/skills/` и `~/.kiro/skills/`, progressive disclosure и opt-in загрузкой в облако (K13). Hooks — JSON-файлы в `.kiro/hooks/<id>.json` (global `~/.kiro/hooks/`), триггеры вроде `PostFileSave`, `PreToolUse`, `PostToolUse`, `Stop`; действия — shell-команды в корне проекта с JSON на STDIN или «agent actions», инжектящие промпт; hooks активируются автоматически при старте сессии (K7). MCP поддерживает stdio, HTTP и SSE, JSON-конфиг, server prompts/resources через `#` и elicitation, на IDE/CLI/Web, но не на Mobile (K14). Powers следуют «the Agent Plugins specification — an open, vendor-neutral format» (K12).

**Субагенты / оркестрация.** «Any custom agent can be invoked as a sub-agent»; orchestrator должен включать инструмент `subagent`; CLI 2.x использует `toolsSettings.subagent.availableAgents`/`trustedAgents`, CLI V3 перечисляет `subagent/<name>` (K11). Субагенты делят steering-файлы, MCP-серверы, доступ к workspace и permissions, но изолируют историю разговора, context window, spec state и hook-триггеры; дефолтный субагент получает те же built-in tools, кастомный использует свою конфигурацию инструментов/разрешений, а в V3/IDE «the parent session's permissions also apply to the sub-agent's tool calls» (K11). Task graphs — DAG, «planned upfront and cannot be modified during execution»; self-loops и mutual loops отклоняются; субагенты идут параллельно, зависимые задачи ждут, а в IDE с выключенными workflows главный агент ждёт всех субагентов (K11). Workflows добавляют более высокий уровень multi-agent оркестрации с сессией на шаг и фоновым исполнением (K20).

**Маршрутизация моделей.** Kiro публикует кредитные множители по моделям: GPT-5.6 Sol 4.4x, Terra 2.2x, Luna 0.6x для запросов до 272K токенов, у всех 1M контекста в IDE/CLI/Web (K26). Custom agents и субагенты могут выбирать модели (K10, K11). Автоматический router на проверенных страницах не документирован.

**Контроль затрат / лимиты.** Free 50 кредитов, Pro $20/1 000, Pro+ $40/2 000, Pro Max $100/5 000, Power $200/10 000; add-on кредиты $0.04; месячные включённые кредиты не переносятся, add-on переносятся и истекают через 12 месяцев; первый апгрейд на Pro даёт остаток месяца бесплатно плюс 500 trial-кредитов на 12 месяцев; Teams $20/место с 500 кредитами на место и pooling, причём «Credit pooling doesn't use overages»; существующие Enterprise-клиенты могут сохранять overages; GovCloud примерно на 20% дороже и без Free tier (K21). Cloud sessions входят в тариф без отдельной платы за compute, до 10 одновременных (K19).

**UX.** Specs дают трёхфазный workflow с явными артефактами; Feature Specs имеют варианты Requirements-First и Design-First, а Quick Spec «auto-generate[s] all three artifacts without approval gates» (K3, K4). Bugfix Specs добавляют третью секцию «Unchanged Behavior (Regression Prevention)», а задачи валидируются property-based тестами на «bug is reproducible / bug is fixed / no regressions» (K5). Checkpoints/rewind дают две разные механики восстановления (K17). Cloud sessions ждут approvals, пока ни один клиент не подключён, и показывают их следующему клиенту (K19).

**Телеметрия / evals.** Enterprise monitoring включает агрегированные дашборды, отчёты по пользователям, prompt logs, AWS CloudTrail, CloudWatch и CSV-экспорт (K24). Продуктовый eval harness на проверенных страницах не документирован.

**Развёртывание / enterprise.** Идентичность завязана на AWS IAM Identity Center с Okta или Microsoft Entra ID как identity sources; Kiro profile — «one profile for each AWS account in a given Region», управляется через Kiro console, а credit pooling делит один пул между seated-пользователями с лимитами на пользователя/группу/профиль (K22). Варианты развёртывания — standalone account vs management+member accounts, с лимитом «up to 20 accounts per AWS Region per organization» (K23). Changelog от 10 ноя 2026 анонсирует Enterprise Management preview: одна policy в AWS console применяется в IDE, CLI, Web и Crew LTS, с allow/deny/ask правилами для моделей, shell-команд, чтения/записи файлов, web search и MCP-инструментов, плюс default model, prompt logging, usage reports и распространение steering-файлов, Skills и Powers; «Models, API keys, and Kiro Crew messaging and network access are denied until a rule allows them» (K25).

**Ценообразование.** Кредитные пакеты по тарифам, team pooling, add-on кредиты (K21).

**Замеченные слабости документации.** Кредитный множитель опубликован, но абсолютная стоимость запроса в кредитах — нет, поэтому пользователь не может посчитать расход только по документации (K21, K26). Workflows явно отделены от трёх других вещей, также называемых «workflow» (встроенные workflow choices IDE, KiroCrew Workflows), — коллизия имён, которую пользователь должен обходить (K20). Страница ACP integrations есть в индексе (K1), но её тело не получено, поэтому ACP-интероп здесь не подтверждён.

### 3.8. Trae

**Архитектура.** Trae — проприетарная IDE плюс «Agent window» для оркестрации нескольких агентов across projects, с cloud tasks и scheduled tasks, плюс SOLO mode, автономно проходящий requirement→code→test→preview→deploy (T3, T18). Встроенные агенты — **Chat** и **Agent**; «Agent» — основной агент разработки проекта, который «first generates an actionable plan based on your goals and project context, then proceeds with development step by step after you confirm the plan» (T1, T2).

**Agent loop.** Документированный workflow: requirement analysis → code research → solution design → implementation → delivery and acceptance (T1). Собственный workflow встроенного Agent: «analyze requirements > generate the PRD and technical solution > generate code > preview the result», с дополнительными шагами вроде чтения файлов проекта, подтверждения scope изменений, организации to-do, вызова субагентов, проверки runtime-результатов и запроса подтверждения на ключевых решениях (T2). SOLO добавляет task management для нескольких одновременных задач и tool panels для редактора, документации и браузера (T3).

**Инструменты.** Встроенные инструменты custom agents — Read, Edit, Terminal, Preview и Web search плюс любые настроенные MCP-серверы (T4). Встроенный Agent автоматически получает все настроенные MCP-серверы с возможностью включать/отключать каждый (T12). Max mode поднимает одну задачу до «up to 200 rounds of tool invocation» и «up to 750 lines can be read at a time» при 1M контекста (T14).

**Стратегия контекста.** Контекст собирается через `@`-меню для файлов, папок, документов, правил и прошлых чатов (T18). Global rules лежат в `~/.trae/user_rules`, project rules — в `.trae/rules/`, а Agent window различает Local и Global применимость для cloud tasks (T10). Memories — global и project-level, хранятся локально и «cannot be shared across devices»; одноразовые инструкции, размытые предпочтения и чувствительная информация не сохраняются автоматически; пользователи могут редактировать `user_profile.md` / `project_memory.md` напрямую, а модель может создавать/обновлять/удалять memories по запросу (T9). Codebase indexing строил workspace-индекс для `@Folder`, игнорируемые файлы никогда не индексировались; фича выводится из эксплуатации для клиентов, выпущенных 2026-10-22 и позже, существующие индексы становятся недоступны, локальные кэши очищаются, а вместо них предлагается "Upload Attachment" (T24). Context compaction доступен только встроенному Agent и другим агентам с Max mode; срабатывает автоматически при переполнении, может быть запущен вручную кнопкой Compact, показывает context usage rate и очищается при новом чате (T15).

**Разрешения / sandbox.** Три preset-режима (T6):
- **Manual Approval** — sandbox включён, перехват опасных команд и file protection включены, каждое требующее approval действие подтверждает пользователь.
- **Automatic Approval** — те же защиты, но решения принимает «TRAE's built-in LLM Guardian» (или кастомная модель пользователя, если выбрана). Недоступен пользователям в США.
- **Full Access** — sandbox выключен, команды выполняются напрямую на хосте, полный read/write файловой системы, все проверки выключены, approval не запрашивается.

Кастомные режимы живут в `~/.trae/permission/global.json` и покрывают `shellSandbox` (`enable`, `onRestrict`), `approval` (`reviewer`, `sceneRules` для `commandAstDangerChecker`, `shellFileProtection`, `deleteToolApproval`, `mcpToolApproval`, `commandRules`, `mcpRules`), `filesystem.default` и `network.default` (T6). Файловая система по умолчанию read-only, кроме файлов/директорий проекта (исключая `.trae`, `.vscode`, `.git`), temp- и cache-директорий и директорий инструментов/зависимостей; сеть разрешена по умолчанию (T6). Sandbox поддерживает macOS, Windows/WSL2 и Linux через Remote SSH + bubblewrap; allowlisted-команды обходят sandbox и выполняются напрямую; `~/.trae/sandbox.json` управляет файловым и сетевым доступом, где «longer and more precise» пути побеждают, read-only побеждает read-write, deny побеждает allow (T7). Не-allowlisted команды идут внутри sandbox, а при сбое система спрашивает, повторить ли снаружи; высокорисковые команды вроде `rm -rf` перехватываются (T7). Страница Auto-run при этом утверждает: «When using the agent, commands are always auto-run outside the sandbox» (T8), что противоречит страницам permissions и sandbox, описывающим sandboxed-исполнение по умолчанию — документное противоречие, а не разрешённое поведение (см. §7).

**Расширяемость.** Custom agents поддерживают smart generation или ручное создание, шарятся ссылкой и импортируются другими; «Callable by other agents» требует английского идентификатора и описания «When to Call»; в tool picker — MCP-серверы плюс Read/Edit/Terminal/Preview/Web search (T4). Субагенты — Markdown + YAML в `~/.trae-cn/agents/` (user) или `{project}/.trae/agents/` (project), с полями `name`, `description`, `model`, `tools`, `disallowedTools`, `mcpServers`; встроенный Agent сопоставляет интент с описаниями и делегирует автоматически; project-субагенты перекрывают user-субагентов, а при дубликатах одного типа «only the first loaded subagent takes effect» (T5). MCP поддерживает `stdio`, `SSE` и `Streamable HTTP` с дисклеймером, что сторонние серверы не ревьюятся и не одобряются (T11). Hooks поддерживают шесть типов событий, global и project `hooks.json`, JSON-контекст в handler и умеют добавлять контекст, перехватывать запрос или продолжать выполнение; создание требует принятия security warning (T23).

**Субагенты / оркестрация.** Встроенный «Agent» по умолчанию включает субагент **Search** и может вызывать custom subagents, MCP-серверы и инструменты; пользователь может явно попросить субагента по имени в промпте (T2). Task management SOLO управляет несколькими задачами в одном проекте (T3). Релиз от 8 окт 2026 добавил Agent window для «orchestrating multiple agents across projects from a single window» (T18).

**Маршрутизация моделей.** Встроенные модели плюс кастомные, добавляемые через preset-провайдера или кастомный API format/URL/model ID/auth; часть моделей доступна только на новых тарифах; TRAE применяет серийные оптимизации промптов и гиперпараметров при выборе серии моделей (T13). Auto mode — единственный вариант на Free, платные тарифы получают «Auto + all models» (T17). Автоматическая политика router, кроме Auto mode, не документирована.

**Контроль затрат / лимиты.** Тарифы: Free $0 только с Auto mode, ограниченным usage, 5 000 completions/мес, 2 одновременными cloud tasks и standard queue; Pro $20 с $20 usage/мес, unlimited autocomplete, до 10 одновременных cloud tasks, fast queue; Pro+ $60 с $60 usage и 15 одновременными; Ultra $200 с $200 usage, 20 одновременными и early access к моделям (T17). При исчерпании месячной квоты On-Demand Usage продолжает работу по API-ценам провайдера с расчётом каждые $3, принудительным расчётом при выключении или окончании периода и повтором платежа каждые 3 минуты (T16). Max mode — отдельная возможность с большим контекстом и числом tool rounds (T14).

**UX.** SOLO даёт task management, tool panels, DiffView, Figma-to-code, интеграции Supabase/Vercel/Stripe, авто-сворачивание чата и кастомные модели (T3). Релиз 8 окт 2026 добавил подключение удалённых директорий, multi-path проекты и desktop companion robot для запуска задач без главного окна (T18). Agent-powered code review поддерживает незакоммиченные изменения, отдельный коммит или различия ветвей, режимы Summarize and Review / Review / Summarize, панель Agent Review и действия Fix / Fix in Chat (T22).

**Телеметрия / evals.** Enterprise console предлагает «multidimensional data insights» (пользователи, тренды активности, AI code generation rate, распределение LLM-вызовов, языков, рейтинги MCP и enterprise agents) и «Audit and logs» по операциям администраторов (T19). Продуктовый eval harness или OTel-экспорт на проверенных страницах не найден.

**Развёртывание / enterprise.** TRAE Enterprise — это Teams-тариф с SSO login, member/seat management, data dashboards, usage control и audit logs; console управляет участниками, местами, usage (basic/excess/resource packs/pay-as-you-go), аналитикой, audit logs, enterprise document sets и enterprise-эксклюзивными AI/security policies (T19). Privacy mode запрещает использовать чат-взаимодействия для аналитики/улучшения/обучения, действует только пока пользователь залогинен и никогда не разрешает использовать файлы кодовой базы для этих целей; файлы кода остаются локально, временно загружаются для вычисления embeddings, после чего plaintext «permanently deleted» (T20). Cloud agents хранят в облаке содержимое репозиториев, rules/state (MCP, rules, memory, runtime, hooks, context), код и данные сессии, «never used for any model training», а удаление сессии безвозвратно удаляет связанные код, чат, контекст и метрики сессии (T21).

**Ценообразование.** Free/Pro/Pro+/Ultra с пулами usage-долларов и уровнями конкурентности плюс on-demand overage (T17, T16).

**Замеченные слабости документации.** SPA `docs.trae.ai` скрывает тела статей от обычных fetch-запросов, а часть страниц рендерится с пустыми таблицами в JSON-payload (T2, T6), что усложняет стороннюю проверку. Страница Auto-run противоречит страницам sandbox о том, выполняются ли команды агента внутри или вне sandbox (T8 vs T6/T7). Codebase indexing выводится из эксплуатации через недели после даты исследования, поэтому любое сравнение на основе `@Folder` уже устарело (T24). Auto Approval недоступен в США — региональное разделение возможностей, которое легко пропустить (T6). Memory device-local, без синхронизации (T9).

### 3.9. Augment Code

**Архитектура.** Augment позиционируется как «the AI-native coding platform built for enterprise-grade software engineering» с двумя основными поверхностями: **Cosmos** (triggers + специализированные агенты + environments) и **Auggie CLI** (agent, context engine, tools в терминале), плюс расширения VS Code и JetBrains (A1, A2, A3). Базовые примитивы Cosmos — Environments, Experts, Sessions, Capabilities и Triggers (A2).

**Agent loop.** Expert «packages a system prompt, user instructions, integrations, environment, model, and workers» (A4). Сессии — место, где «you give the agent a task, watch it run and follow every turn» (A2). Cosmos Advisor умеет создавать и настраивать Experts и environments в разговоре; документация «strongly recommend» управлять Experts через Advisor, а не вручную через формы (A4, A5). Auggie CLI работает интерактивно или с `--print`, а его переписывание 1.x «built on the open-source pi coding agent» (A3, A15).

**Инструменты.** У Auggie есть агент с tool permissions, hooks, MCP, skills, custom slash commands и SDK (A8–A11, A2). Cosmos Experts получают «capabilities and integrations», включая web access, code hosting, ticketing, communication и organization-specific integrations; GitHub, Slack и Linear подключены напрямую, всё остальное — через MCP (A4, A10).

**Стратегия контекста.** Context Engine — главный дифференциатор продукта: Augment хранит workspace в своём облаке и поддерживает «a live understanding of your stack across repos, services, and history» (A12, A16). При открытии workspace с включённым Augment кодовая база «will be automatically uploaded to Augment's secure cloud»; индексация управляется `.gitignore` и `.augmentignore`, обычно занимает меньше минуты, а `.augmentignore` умеет возвращать в индекс gitignored-пути через `!` (A12). Маркетинговая страница заявляет «33% Lower Spend» и «32% Fewer Tokens» на Opus 4.7 против grep-based baseline-агента (A16, claim). У Cosmos Experts есть persistent Memory и Code Review Memory Manager, превращающий фидбек завершённых ревью в repository-specific guidance для будущих ревью (A2, A20).

**Разрешения / sandbox.** У Auggie пять типов разрешений: `allow`, `deny`, `ask-user`, `webhook-policy` и `script-policy`; внутри policy «the first matching rule wins (top-down)», а между policies «the most restrictive matching permission wins» в порядке `deny > webhook-policy > script-policy > ask-user > allow` (A8). `ask-user` без интерактивного UI превращается в deny (A8). Критично: permissions «are honored by the Auggie CLI and by Cosmos cloud agents» но «not enforced in the Augment code extension» (A8) — задокументированный разрыв принуждения. Cosmos environments — либо Augment-hosted cloud sandbox с «Configured egress only», либо self-hosted daemons с сетью хоста и persistent disk (A5). OS-level sandbox, сопоставимого с Cursor/Windsurf/Kiro, на проверенных страницах не найдено.

**Расширяемость.** Skills следуют спецификации agentskills.io с frontmatter `name`/`description` и правилами именования (1–64 символа, lowercase alphanumeric и дефисы, совпадение с именем директории) (A11). MCP-серверы управляются в реестре с обновлением креденшелов, org-level sharing и осознанным выбором между individual accounts и shared connection (A10). Hooks настраиваются в `settings.json`: системный `/etc/augment/settings.json` (immutable), проектные `.augment/settings.json` и `.augment/settings.local.json`, пользовательский `~/.augment/settings.json`; «Augment loads hook configuration from multiple locations ... and runs every matching hook» (A9). Plugins/marketplaces, custom slash commands, ACP mode и TypeScript/Python SDK перечислены в индексе документации (A2).

**Субагенты / оркестрация.** В Cosmos три формы делегирования (A6):
- **Worker** — отдельная сессия Expert с собственной VM, Environment, integrations и permissions; scoped на org или Space; требует явного промпта, потому что «Cosmos does not launch one implicitly».
- **Subagent** — лёгкий helper внутри того же workflow с собственными prompt, context и model, но без конфигурации Expert; scoped на репозиторий.
- **Expert-to-Expert** — координация через общую интеграцию вроде комментариев PR, без прямого запуска.

У всех делегированных агентов собственный context window, system prompt и model, они работают параллельно и отчитываются о прогрессе (A6). Документация советует «prefer Experts over subagents» в Cosmos, потому что Expert — «a real session you can open in the browser, inspect in depth, and reason about independently» (A6). У Auggie CLI отдельно есть встроенные `general-purpose`, `explore` и `plan`, параллельные субагенты и `/agents` для создания кастомных в `.augment/agents/` (A7).

**Маршрутизация моделей.** У Expert есть модель по умолчанию «with room for managed alternatives»; субагенты могут задавать свою модель (A4, A7). Автоматическая политика router на проверенных страницах не документирована.

**Контроль затрат / лимиты.** Цена плоская на команду, не за место: Standard $20/мес «flat, no per-seat charge» с «up to 50 seats» и «$20 of usage included every month»; Business $100/мес flat с $100 usage и до 50 мест; Enterprise custom с «unlimited users», SSO/OIDC/SCIM, CMEK, ISO 42001 и SOC 2; usage покрывает «LLM, Context Engine & compute»; top-ups pay-as-you-go; «No AI training allowed» на всех тарифах (A14). Cloud environments «Billed per minute of uptime»; self-hosted daemons «No additional costs» (A5).

**UX.** Cosmos даёт sessions, Experts, Environments, Spaces (группировка по команде/workstream), PR-to-merge pipeline с ролями author/reviewer/fixer/verifier, Automations и Advisor (A2, A4, A13). Code-review pipeline явно оформлен как «loop engineering»: оптимизировать «verified, understood, merge-ready outcome», а не «an individual review agent or time to first comment» (A13).

**Телеметрия / evals.** Enterprise analytics покрывает monthly active users, lines of code from all sources, user messages и tool calls, плюс per-user колонки (A17). OTel-экспорт или eval harness на проверенных страницах не найдены; в admin checklist audit logs помечены 🚧, а SCIM — «soon» (A18).

**Развёртывание / enterprise.** Enterprise получает dedicated tenant, self-provisioning по домену, SSO (Okta; EntraID «🚧»), SCIM запланирован, allow/block-list доступ и заявки CMEK/ISO 42001/SOC 2 (A14, A18). Environments могут быть Augment-hosted cloud sandboxes или self-hosted daemons, включая Kubernetes через Helm/Minikube и Docker Compose (A5).

**Ценообразование.** Плоская подписка на команду + включённый usage + top-ups (A14).

**Замеченные слабости документации.** Docs помечают Auggie 1.x как «(prerelease)» на нескольких страницах, тогда как changelog называет 1.2.0 «the first stable release of Auggie 1.x» (A3, A8 vs A15) — несоответствие версий и коммуникации. Permissions явно не enforced в IDE-расширении (A8), что ослабляет заявления о паритете поверхностей. Audit logs и EntraID не завершены в admin checklist (A18). Заявления о производительности Context Engine — вендорные бенчмарки без опубликованной методологии на маркетинговой странице (A16).

## 4. Gaps, risks, weaknesses

Раздел фиксирует только слабости со стороны конкурентов: где документированные механики ломаются, где документация противоречит сама себе, где собственные контроли вендора слабее позиционирования и где модель затрат или приватности непрозрачна. Каждый пункт опирается на доказательство и сформулирован как наблюдение о конкуренте.

### 4.1. Контроли безопасности, которые прямо не являются границами

- **Auto-review у Cursor — дефолт и прямо не security boundary.** Документация Cursor говорит: «Auto-review is not a security boundary», потому что «The classifier can make mistakes» (C8, https://cursor.com/docs/agent/security/run-modes, 2026-11-11). Безопасно выглядящий дефолт вероятностный, а детерминированный вариант (Allowlist) требует ручной курации. Риск: пользователь читает «Auto-review» как ревью ревьюером, а не как вероятностный классификатор.
- **Дефолтный read access у Cursor широкий.** `Read Access System` — дефолт, и «The agent can read files outside the workspace without approval» (C8). Это осознанный компромисс удобства, но значит, что граница workspace не является границей чтения.
- **Content exclusion у GitHub не является filesystem boundary.** GitHub пишет, что это «is not a filesystem security boundary and cannot guarantee prevention of every form of file access», «not guaranteed to be respected by third-party MCP servers or clients», и не покрывает symlinks и remote filesystems (G12, https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/content-exclusion, 2026-11-11). Название фичи обещает более сильную изоляцию, чем она даёт.
- **Локальный sandbox GitHub имеет software-only путь.** Встроенные file read/edit инструменты «run as part of Copilot CLI itself rather than as a sandboxed child process» и проверяют политику «in software», а удалённые MCP-серверы вообще вне filesystem policy (G20). OS-принуждение получают только shell-команды, grep/glob, локальные MCP и LSP.
- **Permissions Augment не enforced в IDE-расширении.** Страница Tool Permissions говорит, что правила «Honored by the Auggie CLI and by Cosmos cloud agents; not enforced in the Augment code extension» (A8, https://docs.augmentcode.com/cli/permissions, 2026-11-11). Команда, стандартизировавшая расширение, может считать, что у неё есть политика, которой нет.
- **OS-sandbox Zed узкий.** Sandbox применяется только к `terminal` и `fetch` и явно не к самому Zed, language servers, extensions, tasks, обычным вкладкам терминала, External Agents и Terminal Threads; на Windows он «may not prevent all escape attempts» (Z5, https://zed.dev/docs/ai/sandboxing, 2026-11-11). ACP-агенты не наследуют sandbox вообще.
- **Строгий sandbox Windsurf непортируем.** Fail-closed дизайн («refuse to start rather than running unsandboxed») силён, но OS-sandbox не поддерживается на Windows (жёсткий отказ) и требует `bwrap`/`socat` на Linux; сетевой фильтр документирован как «currently unstable» (W23). Enterprise enforcement на парке Windows — риск доступности, а не только контроль безопасности.
- **Sandbox Kiro выключен по умолчанию.** Локальный command sandbox «is off by default» и доступен только в IDE 1.3+/CLI 2.31+ local V3 sessions (K9, https://kiro.dev/docs/sandbox/, 2026-11-11), поэтому дефолтная поза — правила разрешений плюс парсинг, а не OS-изоляция.

### 4.2. Задокументированные противоречия и неоднозначность

- **Trae одновременно говорит «sandboxed» и «auto-run outside the sandbox».** Страница permissions описывает Manual/Automatic Approval как «Sandbox enabled; commands are executed in an isolated environment», а страница Auto-run — «When using the agent, commands are always auto-run outside the sandbox» (T6 vs T8). Пользователь не может по документации понять, какое утверждение управляет конкретной командой. Это антипаттерн первого порядка: документация по безопасности противоречит сама себе.
- **Automatic Approval в Trae ограничен регионом.** «The 'Automatic Approval' mode is not available to users in the United States» (T6). Возможность, описанная как режим, на деле является региональным правом, и документация упоминает это лишь сноской.
- **Цены JetBrains расходятся.** Licensing docs указывают AI Pro $10 с 10 кредитами и AI Ultimate $30 с 35 кредитами (J10); маркетинг Junie — AI Pro $8.33 и AI Ultimate $25.00 (J20). Только одно из этого может быть list price на данный период; документация не объясняет annual vs monthly и скидку.
- **Матрицы возможностей JetBrains расходятся по skills.** Таблица AI Assistant agents показывает «—» для skills у Junie, тогда как документация Junie заявляет поддержку skills и `.agents` discovery (J2 vs J13). Две страницы JetBrains дают разные ответы об одном продукте.
- **Статус версии Augment противоречив.** Docs-страницы говорят «You're viewing docs for Auggie 1.x.x (prerelease)» (A3, A8), а changelog называет 1.2.0 «the first stable release of Auggie 1.x» (A15). Поддержка stable-релиза с prerelease-баннером усложняет решение о внедрении.
- **Готовность Augment enterprise неполна.** В admin checklist audit logs помечены 🚧, а SCIM обещан «soon», тогда как pricing рекламирует SSO/OIDC/SCIM на Enterprise (A18 vs A14). Покупатель, читающий только pricing, переоценит готовность.
- **Zed продаёт Business до SSO.** Business стоит $30/место с RBAC и data governance, но «SSO, SAML, and SCIM are planned but not currently available» (Z15). Enterprise-закупка обычно требует SSO до пилота, так что это gap go-to-market и безопасности, а не только docs nit.
- **Двойной словарь Windsurf/Devin.** Админская документация говорит, что «'Windsurf' and 'Devin Desktop' refer to the same product», legacy Windsurf Enterprise использует другой dashboard, а пути всё ещё содержат `windsurf` (W21, W13). Cascade — «legacy», но подробно документирован со своими ограничениями (W10). Пользователь не может надёжно отличить текущее поведение от legacy.
- **Kiro называет «workflow» четыре разные вещи.** Workflows (графы оркестрации агентов) явно «distinct from the built-in workflow choices shown when you start an IDE session and from KiroCrew Workflows» (K20) — коллизия имён внутри одного семейства продуктов.
- **Cursor «Auto» разделён на три режима.** Help-страница объясняет: «The old Auto mode was split into 3 new modes: Cost, Balance and Intelligence», а Cursor Router «will launch for Teams and Enterprise» с opt-in для Enterprise (C15). Поведение маршрутизации зависит от тарифа и админского opt-in способами, невидимыми из model picker.
- **У Copilot Workspace нет документации.** Оба проверенных пути отдают 404 (G21, G22; §8.3). Что бы «Workspace» ни значило в сторонних сравнениях, это не текущая документированная поверхность Copilot.

### 4.3. Непрозрачность затрат и лимитов

- **Числовые квоты скрыты у большинства коммерческих продуктов.** Windsurf/Devin публикует «Light quota», «Increased quotas», «Significantly higher quotas», но не числа, при этом extra usage точно priced по API list (W20). Copilot публикует кредиты, но не потребление на задачу; `/fleet` лишь предупреждает, что «may therefore cause more GitHub AI Credits to be consumed» (G5). Cursor публикует тарифы как множители «Plus», а не абсолютные token-бюджеты (C14). Kiro публикует множители по моделям, но не абсолютную стоимость запроса в кредитах (K21, K26). Trae публикует usage-доллары, но скрывает token-математику, пока не прочитаешь таблицы ставок моделей (T17, T13). JetBrains публикует кредиты и $1 за кредит, но не потребление по фичам (J10).
- **«Unlimited» сопровождается оговоркой.** Cursor говорит «no limit on the number of tool calls» (C2), но имеет недельный пул usage с top-offs (C14). Junie Lite говорит, что «virtually unlimited describes normal use, not literally uncapped requests», и «there is no downgrade path» при достижении ёмкости (J17). Zed Personal обещает «Unlimited use with your API keys» (Z15), что unlimited только если вы платите провайдеру.
- **Механики overage резко различаются.** Windsurf: extra usage по API list без лимита на extra usage (W19). Copilot: additional usage требует бюджета, затем оплаты потреблённого overage (G14). Trae: расчёт шагами по $3 и повтор платежа каждые 3 минуты; неудачный платёж блокирует AI-сервис (T16). Kiro: в pooling нет overage, add-on кредиты истекают через 12 месяцев (K21). Это материально разные финансовые риски при одинаковом ярлыке «pay as you go».
- **Конкурентность — скрытое измерение цены.** Trae привязывает конкурентность cloud tasks к тарифу (2/10/15/20) (T17); Devin ограничивает одновременные сессии 10 для Free/Pro и снимает лимит для Max/Teams (W20); Kiro включает до 10 одновременных cloud-сессий (K19); Cursor рекламирует неограниченные параллельные cloud agents, но открывает их с Premium+ (C6). «Параллельные агенты» поэтому означают разное на разных тарифах.
- **Модели ценообразования меняются часто.** Cursor перешёл на The X Subscription с недельными пулами (C14, C15); Windsurf перешёл на квоты в марте 2026 и сохранил часть цен (W19); Bugbot перешёл на usage-based billing (C26); Copilot заменил premium requests на AI credits (G13). Покупатель не может считать единицу учёта стабильной от года к году.

### 4.4. Слабости контекста и retrieval

- **Trae выводит codebase index из эксплуатации.** Автоматическая индексация и `@Folder`-retrieval отключаются для клиентов с 2026-10-22; существующие индексы становятся недоступны, кэш очищается, а вместо них предлагается «Upload Attachment» (T24). Любая оценка качества контекста Trae должна указывать версию клиента, иначе она измеряет удалённую фичу.
- **У Zed нет семантического индекса в документированном пути агента.** Retrieval — grep/find_path/list_directory (Z2). Это прозрачно и приватно, но переносит стоимость обнаружения на больших репозиториях в цикл модели; release notes Zed показывают оптимизации памяти/CPU/диска для длинных agent-тредов (Z21), что согласуется с этой ценой.
- **Cursor явно меняет semantic recall на приватность.** Instant Grep локален и не хранит embeddings (C5). Это законный дизайн, но «codebase indexing» в Cursor — лексический поиск, а не семантический retrieval, и документация этого не скрывает.
- **Семантический индекс Air у JetBrains — marketing-level.** «Air Context's semantic indexing speeds up execution and lowers the cost» (J19) — claim; инженерный блог описывает RAG-систему, но бенчмарк или дизайн индекса на продуктовой странице не опубликован (J21).
- **Заявление Context Engine у Augment — вендорный бенчмарк.** «33% Lower Spend / 32% Fewer Tokens» против grep-based baseline на Opus 4.7 (A16). Методология, датасет и воспроизводимый артефакт на странице не приложены; трактовать как claim.
- **Copilot индексирует каждый репозиторий, но свежесть индекса best-effort.** Первичный индекс ≤60 с, последующие обновления «typically» за секунды (G11). «Typically» — единственная гарантия свежести, что важно для агентов, действующих по только что запушенному коду.
- **Memories Windsurf по дизайну ограничены workspace.** «Memories generated in one workspace will not be available in another» (W9). Это предотвращает утечку между проектами, но и лишает переносимой личной памяти между репозиториями; пользовательское ограничение, редко упоминаемое в сравнениях.

### 4.5. Слабости agent loop и надёжности

- **Legacy Cascade имел жёсткий лимит 40 инвокаций с платным продолжением.** «By default, Cascade can make up to 40 invocations per prompt», каждый `continue` «will count as a new prompt credit», revert «currently irreversible», а параллельные Cascade при правке одного файла «can race» (W10). Это ровно тот антипаттерн, которого не должно быть в текущем продукте; он документирован как история, а не как рекомендация.
- **Семантика hooks Cursor различается между локалью и облаком.** В cloud agents работают только command hooks, user-level hooks недоступны, часть событий не срабатывает, `preToolUse` игнорирует `updated_input` для HTTP MCP, а `postToolUse` получает отредактированный вывод, который не может заменить (C10). Автор hook, протестировавший локально, будет удивлён в облаке.
- **Субагенты Copilot по умолчанию не наследуют repository instructions.** «repository instructions are included for the session agent but are not included for a custom subagent by default» (G6), поэтому делегированный специалист может молча потерять проектные конвенции, если родительский промпт их не передал.
- **Субагенты Cursor стартуют с чистым контекстом.** «Subagents start with a clean context. The parent agent includes relevant information in the prompt since subagents don't have access to prior conversation history» (C11). Это чистая модель изоляции, но она перекладывает суммаризацию на родителя и делает качество делегирования зависимым от качества промпта.
- **Task graphs Kiro не адаптируются.** «Task graphs are planned upfront and cannot be modified during execution»; self-loops и mutual loops отклоняются (K11). Это даёт детерминизм и предотвращает runaway-циклы, но не позволяет перепланировать, если средний шаг обнаружил новую работу.
- **Non-interactive исполнение Kiro превращает каждый ask в deny.** «In non-interactive execution, every ask is treated as a deny» (K8), поэтому автоматизация поверх Kiro требует полного allowlist, иначе встанет.
- **Поведение агентов JetBrains раздроблено.** Одна IDE предоставляет Junie, Claude Agent, Codex и Copilot с разными наборами режимов, разными файлами инструкций (`AGENTS.md` vs `CLAUDE.md`), разной поддержкой `.aiignore` и разной поддержкой skills (J2). Команда не может предполагать единую политику.
- **Trae: только встроенный Agent может вызывать кастомных агентов.** «Currently, only the built in 'Agent' can call custom agents» (T4), поэтому кастомные агенты не строят собственные иерархии, а при дубликате имени загружается только первый файл, остальные молча игнорируются (T5).
- **Workers Augment никогда не запускаются неявно.** «Cosmos does not launch one implicitly» (A6). Это безопасно, но manager Expert должен нести явные инструкции делегирования, а их отсутствие молча деградирует до отсутствия параллельности.

### 4.6. Слабости приватности и телеметрии

- **AI Assistant JetBrains собирает полные диалоги с LLM только по opt-in.** Опция «Send detailed code-related data» «disabled by default», но при включении включает «the full communication between you and the LLM (both text and code fragments)» и используется для обучения (J3). Дефолт хороший; охват opt-in необычно широк.
- **Privacy Mode Trae привязан к сессии/аккаунту.** «Privacy mode is only effective when your TRAE account is logged in. Once logged out, Privacy mode is no longer active» (T20). Разлогиненный редактор молча меняет режим использования данных.
- **Cloud agents Trae хранят содержимое репозитория в облаке.** Политика перечисляет репозитории, rules/state (MCP, rules, memory, runtime, hooks, context), код и метрики сессии, хранящиеся в облаке, «never used for any model training», удаляемые только при удалении сессии пользователем (T21). Это более широкий облачный след, чем предполагает позиционирование «локальная IDE».
- **Cloud Agents Cursor — единственная фича, хранящая код.** Privacy doc прямо говорит: «Cloud Agents are the only feature that requires Cursor to store code ... Stored temporarily while the agent runs ... Deleted after the agent completes», и рекомендует не включать их, если политика запрещает хранение кода (C17). Это необычно честно и полезно для security review.
- **Модели с ограниченным retention у Cursor требуют approval.** Некоторые модели Claude Fable «require data retention with the provider and fall outside these agreements»; запросы «fail until the model's data retention policy is approved from the dashboard» (C17). Модель может быть видима, но недоступна, пока админ не сделает opt-in.
- **Телеметрия Zed может связываться с личностью.** Usage привязан к случайному telemetry ID, и «If you've authenticated, this ID may be linked to your [account]» (Z14). Клиентские метрики не содержат код, но связь с личностью условна и не является opt-in на уровне события.
- **Enterprise data plane Windsurf изменился вместе с брендом.** Legacy Windsurf Enterprise controls отображаются на Devin team settings, причём документация перечисляет, какие контроли «carry over, are replaced by permissions, or are unsupported» (W21). Enterprises не могут предполагать паритет фич после миграции.
- **Augment загружает workspace по умолчанию.** «When you open a workspace with Augment enabled, your codebase will be automatically uploaded to Augment's secure cloud» (A12). Opt-out — через ignore-файлы, а не через явный режим «не загружать», то есть дефолт — облачная индексация.

### 4.7. Слабости UX и оценки

- **Лендинг документации Cursor — каталог моделей.** `cursor.com/docs` описывает позиционирование и модели, а не loop/compaction/tool-семантику (C1); реальные механики разбросаны по `/docs/agent/overview`, `/docs/agent/security/run-modes`, `/docs/subagents` и `/docs/agent/hooks`. Discoverability плохая для продукта такой сложности.
- **Документация Cascade у Windsurf — риск тупика.** Cascade подробно документирован, хотя legacy и не может начинать новые разговоры (W10), а Workflows документированы как текущая фича, хотя Devin Local «does not support them» (W12, W10).
- **У трёх продуктов JetBrains нет единой страницы выбора.** AI Assistant, Junie и Air пересекаются; страница AI Assistant agents опускает skills у Junie, тогда как документация Junie их заявляет (J2, J13); Air GA blog описывает интеграцию IDE MCP/skills/debugger, которой нет в AI Assistant help (J21).
- **Ни один продукт не публикует воспроизводимый eval harness.** Cursor поставляет Agent SDK с evals (C21), но API evals на проверенных страницах не описан; ни один из восьми не публикует публичный per-release scorecard качества агента на проверенных страницах. Release notes Zed сообщают об улучшениях памяти/CPU/диска, а не о task success rate (Z21); changelog Kiro сообщает фичи, а не метрики качества (K25).
- **Документация Trae плохо машиночитаема.** SPA возвращает ту же 1,9-МБ оболочку для `/llms.txt` и `/sitemap.xml`; JSON статьи содержит пустые таблицы там, где UI, вероятно, что-то рендерит (T2, T6). Это проблема docs-платформы, но она напрямую увеличивает стоимость независимой проверки.

## 5. Strengths and differentiators

Наблюдения со стороны конкурентов: что каждый продукт делает действительно отличительно и какая механика создаёт разницу. Формулировки «стоит изучать» относятся к механике, а не к паритету ZCode.

### 5.1. Cursor

- **Browser как first-class и token-efficient инструмент.** Логи браузера «are written to files that Agent can grep and selectively read» вместо суммаризации после каждого действия; скриншоты идут через file-reading tool «as images rather than relying on text descriptions»; агент получает подсказку определять запущенные dev-серверы и корректные порты (C7, https://cursor.com/docs/agent/tools/browser.md, 2026-11-11). Дифференциатор: log-to-file + grep — обобщаемый паттерн для любого шумного вывода инструмента, не только браузера.
- **Самая широкая hook-поверхность с семантикой отказа на hook.** 18 agent-событий + 2 Tab-события + app lifecycle, типы command и LLM-prompt, четыре слоя источников, `failClosed` и документированные ограничения облака (C10). Дифференциатор: hooks оформлены как продуктовый контракт с явными правилами слияния и отказа.
- **Evals как версионируемые файлы репозитория.** Agent SDK и evals объявлены в changelog (C21). Дифференциатор: оценка живёт рядом с кодом, а не в дашборде вендора, хотя детали API в этой ветке не перезапрашивались.
- **Cloud Agents как полноценные desktop-VM с computer use.** Каждый агент получает изолированную VM с полным desktop, мышью/клавиатурой, браузером, dev-серверами; HTTP MCP проксируется так, что конфиги серверов «never present in the cloud agent's VM environment»; short-lived OIDC JWT; артефакты прикрепляются к PR (C6, C20). Дифференциатор: HTTP MCP proxying через бэкенд — конкретный паттерн изоляции креденшелов.
- **Приватность описана явно и по поверхностям.** Локальный поиск не выгружает пути/код и не хранит embeddings (C5); Privacy Mode гарантирует отсутствие обучения со стороны Cursor и провайдеров и может быть включён обязательным для команды (C25); Cloud Agents — единственная фича, хранящая код, и она удаляется после запуска (C17); модели с ограниченным retention требуют approval в дашборде (C17). Дифференциатор: privacy-документация называет исключение, а не заявляет сплошную локальность.
- **Самый зрелый enterprise-стек среди восьми.** SSO/SCIM/RBAC/MDM, organization groups с most-permissive union для доступа к моделям, ограничение BYOK, CMEK, private connectivity, self-hosted cloud-agent machines и Enterprise-only OTel export с opt-in захватом контента (C13, C16–C19).

### 5.2. Windsurf / Devin Desktop

- **Fail-closed sandbox.** При невозможности разрешить sandbox «the CLI will refuse to start rather than running unsandboxed» (W23). Дифференциатор: доступность сознательно приносится в жертву security-инварианту, а режимы отказа (Windows unsupported, отсутствие `bwrap`/`socat`, невалидные scopes) перечислены.
- **Sandbox выводится из permission scopes.** Writable-пути «are derived from granted `Write(...)` permission scopes plus the workspace directory»; `Read(...)` deny-правила скрывают пути «from sandboxed commands entirely»; выданные посреди сессии `Write` расширяют sandbox для последующих команд (W23, W5). Дифференциатор: один язык политики управляет и approvals, и OS-границей, вместо двух параллельных конфигов.
- **Двухуровневая экономика моделей: Adaptive + Fusion.** Adaptive маршрутизирует по запросу; Fusion соединяет frontier lead с дешёвым sidekick и биллит каждого по своей ставке, с выбираемыми lead/effort/sidekick/Fast Mode (W16, W17). Дифференциатор: контроль затрат выражен как топология моделей, а не только как квота.
- **Импорт конфигурации из восьми инструментов.** Devin CLI импортирует rules и MCP-конфиги из Cursor, Windsurf, Claude Code, GitHub Copilot, Codex, Kiro, OpenCode и Zed (W24). Дифференциатор: миграция — документированное runtime-поведение, снижающее стоимость переключения в пользу вендора.
- **Один harness, две поверхности.** «Devin Local is our next-generation agent harness shared with Devin CLI» и «a customization you write for one works in the other» (W3, W22). Дифференциатор: нет расхождения desktop/CLI в семантике кастомизаций.
- **Agent Command Center.** Локальные и облачные сессии в одном представлении, блокировка сессии во время работы, ветвление duplicate session, редактируемые queued messages и одно OS-уведомление на сессию для Devin Local и ACP-агентов (W14).

### 5.3. GitHub Copilot

- **Явная таксономия автономности.** Collaborative, asynchronous и automated сессии с заявлением об ответственности: пользователь остаётся ответственным за цель, ограничения, доступ и ревью (G4). Дифференциатор: продукт называет обязанность человека, а не подразумевает полную автономность.
- **Платформенная оркестрация.** `/fleet` превращает главного агента в orchestrator, который дробит работу и запускает субагентов параллельно (G5); cloud-сессии «shared and resumed across clients» (G1). Дифференциатор: один объект сессии охватывает web, mobile, IDE и CLI.
- **Выбор среды — продуктовое решение первого класса.** Cloud sandbox (multi-repo, org firewall) vs GitHub Actions (один репозиторий, custom compute, лимит 59 минут) vs remote/self-hosted (G1, G3). Дифференциатор: документация подаёт trade-offs таблицей возможностей, а не скрытыми дефолтами.
- **Governance под смешанное лицензирование.** Copilot code review можно включить участникам организации без лицензии Copilot через две policy, одна из которых разрешает AI-credit paid usage (G10). Дифференциатор: security review отвязан от выдачи seat, что важно для крупных org.
- **MCP allowlisting с честным ранжированием принуждения.** `managed-settings.json` — «Generally available» с matching «by name, URL, or stdio commands», а custom registry — «Public preview, not prioritized» и «Users can bypass the restriction by editing configuration files» (G16). Дифференциатор: документация ранжирует силу контроля, а не подаёт все allowlists как эквивалентные.
- **OTel с независимо включаемыми capture classes.** Identity, prompts, responses, tool arguments, tool output и policy detail включаются отдельно; дефолт исключает всё; fine-grained capture работает в CLI/app/VS Code Agent Host (G15). Дифференциатор: privacy телеметрии — поверхность политики, а не boolean.
- **Семантическая индексация в масштабе репозиториев без лимита.** «There is no limit to how many repositories you can index» (G11). Дифференциатор: предсказуемая экономика индексации для крупных организаций.

### 5.4. JetBrains AI

- **IDE-интеллект, отданный агентам через MCP.** Агенты могут «check inspections, run your build and run configurations, query your databases, and use the IDE's own refactorings», а в IntelliJ IDEA/CLion «drive the debugger» (J21). Дифференциатор: агент использует семантическую модель IDE, а не выводит её заново из текста.
- **Agent-agnostic хост с ACP.** AI Assistant хостит Junie, Claude Agent, Codex и Copilot рядом плюс курируемые/кастомные ACP-агенты, причём ACP-агенты не требуют подписки JetBrains AI (J2, J4, J22). Дифференциатор: IDE конкурирует хостингом и code intelligence, а не одним проприетарным агентом.
- **Кросс-инструментальный импорт как повторяющийся паттерн.** Skills импортируются из `~/.codex/skills` и `~/.claude/skills` (J7); субагенты автоимпортируются из `.cursor/agents/`, `.claude/agents/` и `.codex/agents/` (J13); MCP-конфиг импортируется из Claude Desktop (J6); Junie находит guideline-файлы других агентов и предлагает импорт в `.junie/AGENTS.md` (J16). Дифференциатор: миграция встроена в IDE.
- **Plan mode со структурированным, версионируемым артефактом.** Plan mode создаёт живой design document, сохраняемый как Markdown-файл, с вкладками Requirements, Technical design, Testing и Delivery steps и явными действиями Confirm/View/Open/Save-and-stop (J12). Дифференциатор: план — инспектируемый файл, а не только текст чата.
- **Бесплатная постоянная базовая модель.** Junie Lite — постоянный бесплатный тариф (сейчас Qwen 3.6 27B) без опубликованной квоты, без лимита tool calls и с инференсом «exclusively on JetBrains infrastructure» без передачи данных провайдеру (J17). Дифференциатор: нулевой ценовой пол с чёткой границей данных.
- **Переносимость подписки.** Air позволяет «Bring your existing provider subscription or API keys, or even base URL» и «Switch between subscriptions – even mid-session»; организации могут один раз добавить ключи Bedrock/OpenAI/Anthropic для всех разработчиков (J19, claim). Дифференциатор: BYOK переносим по запросу, а не по установке.

### 5.5. Zed AI

- **Open-source редактор с реальной протокольной границей.** GPL-3.0-or-later с компонентами Apache-2.0 (Z18) и ACP как Apache-2.0-протокол, стандартизующий связь editor↔agent «similar to how the Language Server Protocol (LSP) standardized language server integration» (Z8, W13, Z20). Дифференциатор: редактор может хостить агентов конкурентов, не встраивая их рантаймы.
- **Редактор хостит thread, агент владеет всем остальным.** «Zed hosts the thread», а внешний агент «owns its own runtime, auth, model selection, tools, and native configuration»; биллинг и юридические условия «between you and the agent provider», и «Zed does not charge for External Agents» (Z8). Дифференциатор: чистая граница ответственности и биллинга.
- **Точная, маленькая грамматика разрешений.** Rust-regex-паттерны с регистронезависимостью, шесть уровней приоритета и ровно один класс жёстких защит: рекурсивное удаление `/`, `~`, `.` и `..`, проверяемое и по сырой команде, и по каждой разобранной подкоманде (Z3). Дифференциатор: встроенные правила безопасности перечислимы и документированы как закрытый набор.
- **Profiles и permissions — разные концепции.** Profiles управляют доступностью инструментов и моделью; permissions — allow/deny/confirm (Z4). Дифференциатор: выбор возможностей не смешан с авторизацией.
- **Privacy-дефолты с названными исключениями.** По умолчанию нет retention; no-training и ZDR для hosted-моделей, кроме provider-designated safety-retention моделей; API-ключи в системном keychain; edit prediction — отдельный per-keystroke путь данных (Z13). Дифференциатор: privacy-таблица по путям запросов вместо одной фразы политики.
- **Multiplayer-коллаборация встроена в редактор.** Channels, contacts, private calls, voice и общий доступ к файловой системе проекта с явным предупреждением, что «Sharing a project gives collaborators access to your local file system within that project» (Z16). Дифференциатор: коллаборация — first-class поверхность, а не плагин.

### 5.6. Kiro

- **Spec-driven разработка как продуктовый примитив.** Три артефакта (`requirements.md`/`bugfix.md`, `design.md`, `tasks.md`), трёхфазный workflow, варианты Requirements-First и Design-First и Quick Spec, который «auto-generate[s] all three artifacts without approval gates» (K3, K4). Bugfix Specs добавляют явную секцию «Unchanged Behavior (Regression Prevention)» и задачи property-based тестов на «bug is reproducible / bug is fixed / no regressions» (K5). Дифференциатор: спецификация — это интерфейс, а предотвращение регрессий — обязательный артефакт.
- **Steering с четырьмя режимами включения.** `always`, `fileMatch`, `manual` (также slash-команды) и `auto` (совпадение по description, также slash-команды), плюс always-on `AGENTS.md`, приоритет workspace и распространение через MDM/центральный репозиторий (K6). Дифференциатор: инъекция контекста — типизированная, инспектируемая политика, а не одна папка «rules».
- **Разрешения, спроектированные вокруг парсинга shell.** Compound-команды делятся и каждая подкоманда оценивается; комбинированные короткие опции проверяются; опции, запускающие другую программу, «never treated as read-only»; неразбираемые команды блокируются; non-interactive ask становится deny; workspace-правила живут вне репозитория, поэтому «A cloned repo cannot inject permission rules» (K8). Дифференциатор: самая конкретная shell-safety-конструкция среди восьми.
- **Lockdown недоверенного workspace.** В недоверенном workspace Kiro «Asks before every shell command starts, including background processes» и «Does not load the workspace's custom agents, Steering files, MCP server configuration, or Skills» (K8). Дифференциатор: доверие — сессионный гейт на загрузку конфигурации, а не только на исполнение команд.
- **Powers как управление бюджетом контекста.** Вместо загрузки всех MCP-инструментов powers активируются по ключевым словам и грузят только нужные `plugin.json` + skills + `mcp.json`; мотивация — пять MCP-серверов, съедающих «50,000+ tokens, 40% of your context window» до первого промпта (K12). Дифференциатор: раздувание tool-схем трактуется как измеряемая стоимость, а экспертиза упаковывается, чтобы её избежать.
- **Workflows как долговечные фоновые графы агентов.** Графы шагов/последовательностей/циклов/параллельных ветвей, каждый шаг в собственной сессии со свежим контекстом, с паузой/возобновлением/коррекцией, сохраняемые как переиспользуемые recipes (K20). Дифференциатор: оркестрация — first-class долговечный объект, а не один длинный thread.
- **Cloud session как объект уровня аккаунта.** Старт в браузере, закрытый ноутбук, подключение с телефона/терминала/IDE; approvals ждут следующего клиента; состояние переживает машину; до 10 одновременных сессий включено (K19). Дифференциатор: сессия отвязана от клиента.
- **Enterprise management с якорем в AWS.** IAM Identity Center/Okta/Entra, один Kiro profile на AWS-аккаунт на регион, credit pooling с лимитами на пользователя/группу/профиль, GovCloud (+20%, без Free tier) и одна console-policy, распространяющая rules/settings/steering/Skills/Powers на IDE, CLI, Web и Crew LTS (K22, K23, K25). Дифференциатор: распространение политики использует существующее AWS-governance, а не новый control plane.

### 5.7. Trae

- **Встроенный основной агент с явным гейтом PRD/design.** «Agent» генерирует PRD и техническое решение и ждёт подтверждения до реализации (T2). Дифференциатор: plan-артефакт — гейт в дефолтном потоке, а не опциональный режим.
- **Авто-вызов субагентов по описанию.** Встроенный Agent сопоставляет интент пользователя с полями `description` субагентов и делегирует автоматически, причём project-субагенты перекрывают user-субагентов (T5). Дифференциатор: маршрутизация — model-driven по естественно-языковым описаниям, а не по slash-командам.
- **Режим approval через LLM Guardian.** Automatic Approval отправляет обычно гейтуемые операции LLM-ревьюеру; кастомная модель пользователя может быть ревьюером; режим недоступен в США (T6). Дифференциатор: отдельная опция «модель одобряет модель» с документированным региональным ограничением.
- **Sandbox, ограниченный директориями зависимостей и тулчейнов.** Read/write по умолчанию включает файлы проекта (кроме `.trae`, `.vscode`, `.git`), temp, cache, `~/.local/{lib,bin,share}` и языковые тулчейны — конкретный ответ на «агенту нужно ставить зависимости, но не читать мои документы» (T6, T7).
- **Self-serve конфиг разрешений.** `~/.trae/permission/global.json` открывает `shellSandbox`, `approval.reviewer`, `sceneRules` для AST danger checks / file protection / delete / MCP approval, `filesystem.default` и `network.default` (T6). Дифференциатор: политика ревью — читаемый файл, а не скрытая настройка.
- **Cost UX с явным мелким расчётом.** On-demand usage рассчитывается каждые $3, при выключении и по окончании периода, с повтором платежа каждые 3 минуты (T16). Дифференциатор: шаги расходов мелкие и предсказуемые, хотя неудачный платёж блокирует сервис.
- **Agent-powered code review с визуальными сводками.** Review поддерживает незакоммиченные изменения, отдельный коммит или дифф ветвей, режимы Summarize/Review и логическую flow-диаграмму изменений (T22). Дифференциатор: артефакт ревью визуальный, а не только inline-комментарии.
- **SOLO как полный build loop.** SOLO проходит requirement→code→test→preview→deploy с task management, tool panels, Figma-to-code и интеграциями Supabase/Vercel/Stripe (T3). Дифференциатор: собранный путь от идеи до задеплоенного приложения для пользователей вне IDE-центричного workflow.

### 5.8. Augment Code

- **Таксономия делегирования с явным весом.** Workers (отдельный Expert, своя VM/Environment/integrations) vs subagents (лёгкие, repo-scoped) vs Expert-to-Expert (координация через PR), с таблицей «когда что» и рекомендацией предпочитать Experts, потому что это инспектируемые сессии (A6). Дифференциатор: самая явная модель стоимости делегирования среди восьми.
- **Плоские цены на команду.** Standard $20/мес flat до 50 мест с $20 usage, Business $100/мес flat с $100 usage, Enterprise custom с unlimited users (A14). Дифференциатор: стоимость не масштабируется по местам, что меняет экономику внедрения в больших командах.
- **Self-hosted environments, включая Kubernetes.** Cloud sandboxes с configured egress или self-hosted daemons на ноутбуке, VM или Kubernetes; self-hosted имеет persistent disk и «No additional costs» (A5). Дифференциатор: регулируемые данные могут оставаться на территории клиента, пока Cosmos продолжает оркестрацию.
- **Пять типов разрешений, включая делегирование внешней политике.** `allow`, `deny`, `ask-user`, `webhook-policy` и `script-policy` с most-restrictive-wins между policies (A8). Дифференциатор: политику можно делегировать внешнему HTTP-endpoint или локальному скрипту, что стыкуется с существующими enterprise policy engines.
- **PR-to-merge как multi-Expert pipeline.** PR Author/PR Fixer, Risk Analyzer, Deep Reviewer, Pair Reviewer, Verifier и человеческое решение о мерже в рамке «loop engineering», оптимизированной под merge-ready outcome (A13). Дифференциатор: ревью разложено на специализированные роли, а не один reviewer-agent.
- **Context Engine как измеримый рычаг затрат.** Вендор подаёт retrieval как драйвер «more solved work per budget» и публикует сравнение spend/token (A16, claim). Дифференциатор: контекст позиционируется как экономическая задача с бенчмарк-заявлением (методология не подтверждена).
- **Code Review Memory.** Фидбек завершённых ревью становится «durable, repository-specific guidance for future reviews» через workflow capture→curate→load, хранится в общем VFS организации и scoped по репозиторию (A20). Дифференциатор: фидбек ревью сохраняется как знание репозитория, а не расходуется однократно.

## 6. Candidate recommendations

Кандидатные рекомендации написаны для родительского синтеза. Каждая называет механику конкурента, доказательство, почему её стоит изучать и что не стоит копировать. Это не задачи внедрения в ZCode; ни один файл и ни одна строка ZCode не цитируются, и ни одна рекомендация не предполагает, что у ZCode есть или нет соответствующий компонент.

### 6.1. Механики, которые стоит изучать

**R1. Разделять решение об одобрении и границу исполнения.**
- Доказательство: Cursor разделяет Run Modes (политика approval) и `sandbox.json` (что доступно sandboxed-команде) (C8); Windsurf выводит writable-пути sandbox из выданных `Write(...)` scopes и скрывает пути из `Read(...)` deny (W23, W5); Copilot запускает shell под OS deny-by-default policy, а встроенные файловые инструменты перепроверяют её в software (G20); Kiro разделяет permission rules и опциональный локальный command sandbox, выключенный по умолчанию (K8, K9).
- Почему изучать: один «режим», кодирующий одновременно «можно ли?» и «чего он может коснуться?», порождает противоречие Trae, где документация говорит и «sandboxed», и «auto-run outside the sandbox» в одном продукте (T6 vs T8). Два названных слоя снимают эту неоднозначность.
- Что не копировать: дефолтный `Read Access System` у Cursor разрешает агенту читать вне workspace без approval (C8); Kiro поставляет OS-sandbox выключенным (K9). Оба — разрешительные дефолты, ослабляющие слоёную модель.

**R2. Выводить sandbox из политики разрешений, а не поддерживать два конфига.**
- Доказательство: у Windsurf scopes `Write`/`Read` напрямую определяют writable/readable пути sandbox, а выданные посреди сессии гранты расширяют sandbox (W23); у Trae `global.json` разделяет `shellSandbox`, `approval`, `filesystem` и `network`, но держит их в одном policy-файле (T6).
- Почему изучать: два источника истины расходятся. Один источник с явным «most restrictive wins» тестируем.
- Что не копировать: жёсткий отказ Windsurf на Windows без документированного деградированного режима (W23) и предупреждение о «unstable» сетевом фильтре (W23); fail-closed дизайну нужна документированная и протестированная матрица платформ.

**R3. Парсить shell-ввод до применения правил; неразбираемый ввод считать deny/ask.**
- Доказательство: Kiro делит compound-команды, оценивает каждую подкоманду, проверяет комбинированные короткие опции, отказывается считать опции запуска программ read-only и блокирует команды, которые не может разобрать достаточно хорошо; non-interactive ask становится deny (K8). У Trae есть явное scene-правило `commandAstDangerChecker` и перехват высокорискового `rm -rf` (T6, T7). Zed проверяет жёсткие правила рекурсивного удаления и по «both the raw command and each parsed sub-command» (Z3).
- Почему изучать: строковые prefix-allowlists обходятся через `;`, `&&`, pipe и цепочки опций. Парсинг — разница между политикой и пожеланием.
- Что не копировать: список жёстких защит Zed намеренно минимален («There are no other built-in rules») (Z3); это элегантно, но оставляет большинство деструктивных команд на пользовательскую политику. Строгость Kiro лучше для безопасности и хуже для удобства; компромисс должен быть явным.

**R4. Делать оговорку «не security boundary» структурной, а не только текстовой.**
- Доказательство: Cursor документирует, что классификатор Auto-review «can make mistakes» и не является security boundary (C8); GitHub документирует content exclusion как «not a filesystem security boundary» (G12); Augment документирует, что permissions не enforced в IDE-расширении (A8); Zed документирует, что sandbox исключает External Agents (Z5).
- Почему изучать: честная маркировка позволяет enterprise-ревьюерам сопоставить контроли с реальными гарантиями. Продукт, заявляющий границу, которой нет, создаёт аудиторский риск для клиентов.
- Что не копировать: поставку вероятностного дефолта (Cursor Auto-review) и не-enforced поверхности (Augment extension) под названиями, подразумевающими принуждение. Либо принуждать, либо переименовывать.

**R5. Рассматривать делегирование субагенту как решение об изоляции контекста с явной стоимостью.**
- Доказательство: субагенты Explore/Browser у Cursor существуют потому, что исследование и DOM-вывод «would bloat the main context» (C11); Kiro изолирует историю, context window, spec state и hook-триггеры на субагента, разделяя steering/MCP/permissions (K11); Augment различает тяжёлые Workers и лёгкие Subagents плюс явную координацию Expert-to-Expert (A6); субагенты Devin Local делят tools/codebase context, но «operate in their own conversation chain» (W3); субагенты Copilot имеют свой context window, но не наследуют repository instructions по умолчанию (G6).
- Почему изучать: четыре продукта сошлись на «отдельный context window, общая или явно ограниченная политика», а режимы отказа известны (потерянные инструкции, устаревший контекст). API делегирования должно явно описывать правила наследования.
- Что не копировать: неявный запуск worker или неявные допущения о наследовании (G6, A6). Родитель должен передать то, что нужно ребёнку, а конфиг — сказать, что общего.

**R6. Делать планы и спецификации инспектируемыми файлами с гейтом ревью, а не текстом чата.**
- Доказательство: Plan Mode Cursor сохраняет планы в домашнюю директорию с «Save to workspace» (C3); Plan mode JetBrains сохраняет Markdown-план, показывает вкладки Requirements/Design/Testing/Delivery и предлагает Save-and-stop (J12); Kiro пишет `requirements.md`/`design.md`/`tasks.md` с вариантами Requirements-First и Design-First (K3, K4) и Bugfix Specs с «Unchanged Behavior» и PBT-задачами (K5); Agent в Trae генерирует PRD и техническое решение и ждёт подтверждения (T2); plan mode в Copilot CLI строит структурированный план (G2).
- Почему изучать: файлы ревьюятся, диффятся, версионируются и переиспользуются; планы в чате — нет. Quick Spec у Kiro показывает escape hatch для мелких задач («without approval gates») (K3), что избегает spec-overhead на тривиальной работе.
- Что не копировать: принудительный трёхфазный spec на каждой задаче. Документация Kiro сама ограничивает specs сложными фичами и направляет багфиксы в отдельный вариант (K3, K5); Trae всегда гейтует на подтверждении PRD, что тяжелее для мелких изменений (T2).

**R7. Compaction должен быть видимой и управляемой runtime-заботой.**
- Доказательство: Kiro документирует автоматический compaction плюс ручной `/compact` (только CLI) и индикатор использования контекста на всех поверхностях (K16); Trae показывает context usage rate и кнопку Compact, сжимая только встроенный Agent и Max-mode агентов (T15); Zed отдаёт feature-specific настройку `agent.compaction_model` (Z17); hook-list Cursor включает `preCompact` (C10).
- Почему изучать: длинные сессии ломаются на границах контекста; пользователям нужно видеть usage и запускать compaction, а hooks нужен pre-compaction seam.
- Что не копировать: полностью скрывать compaction (несколько продуктов его не документируют). Ограничение compaction отдельными типами агентов у Trae (T15) создаёт несогласованное поведение между агентами.

**R8. Давать каждому механизму инъекции контекста типизированный режим активации.**
- Доказательство: steering Kiro имеет `always`/`fileMatch`/`manual`/`auto` с alias'ами slash-команд (K6); rules Cursor имеют Always Apply/Apply Intelligently/Apply to Specific Files/Apply Manually плюс приоритеты Team/Project/User/AGENTS.md (C4); project rules JetBrains имеют Always/Manually/By model decision/By file patterns/Off (J8); Copilot имеет repository-wide, path-specific с `applyTo` и nearest-`AGENTS.md` (G18).
- Почему изучать: «always-on rules» не масштабируются; типизированная активация — разница между always-on файлом на 500 строк и запрашиваемой политикой. Она также делает приоритеты тестируемыми.
- Что не копировать: молчаливое игнорирование правдоподобного файла. `.md` в `.cursor/rules` «is ignored by the rules system because it has no frontmatter» (C4); нужна диагностика, а не тишина.

**R9. Маршрутизацию моделей выражать как политику с аудируемой единицей учёта.**
- Доказательство: Adaptive у Windsurf (маршрутизация по запросу) и Fusion (топология lead+sidekick) (W16, W17); Cursor Router Cost/Balance/Intelligence плюс инструменты под модель (C15, C2); Fusion-маршрутизация Copilot (G19); plan-on-strong/implement-on-fast у JetBrains (J12, J20) и смена подписки mid-session (J19); Kiro публикует кредитные множители по моделям (K26).
- Почему изучать: маршрутизация — способ вендоров контролировать затраты без потери возможностей. Явные именованные режимы делают расход объяснимым.
- Что не копировать: маршрутизацию, которая невидимо меняет модель под общим ярлыком «Auto» с зависимой от тарифа семантикой (разделение Auto у Cursor, C15), или маршрутизацию, где множитель опубликован, а абсолютная стоимость — нет (K26).

**R10. Публиковать квоты числами либо публиковать единицу и формулу.**
- Доказательство: Copilot публикует кредиты по тарифам (G13); Kiro публикует кредиты по тарифам и множители по моделям (K21, K26); Cursor публикует множители тарифов и недельные пулы (C14); JetBrains публикует $1=1 кредит (J10); Trae публикует usage-доллары и шаг расчёта $3 (T16); Windsurf публикует только качественные уровни (W20).
- Почему изучать: покупатель может сравнить Copilot/Kiro/Cursor/JetBrains/Trae по единице, но не может сравнить «Significantly higher quotas» у Windsurf. Связка «множитель + пул» у Kiro — ближайшая к вычислимой.
- Что не копировать: качественные ярлыки квот в сочетании с точно priced overage (W20) — асимметрия скрывает базовый allowance, но раскрывает штраф.

**R11. Делать артефакты моделей файлами с открытыми стандартами.**
- Доказательство: Agent Skills `SKILL.md` поддерживается Copilot (G8), Devin (W22), Zed (Z10), Kiro (K13), JetBrains (J7), Augment (A11, где назван agentskills.io), а индекс документации Cursor перечисляет skills как открытый стандарт (C21). ACP — Apache-2.0 и реализован Zed, Devin, JetBrains и Augment (Z20, W13, J4, A19). Powers Kiro используют «the Agent Plugins specification — an open, vendor-neutral format» (K12).
- Почему изучать: один и тот же skill-файл работает в разных продуктах, что снижает стоимость авторинга и делает skills ревьюируемыми в репозитории. Сходимость к открытым форматам — рыночный паттерн, а не фича одного вендора.
- Что не копировать: изобретение приватного bundle-формата для того же контента. Двойные форматы Cursor — «Agent Plugins (`plugin.json`)» и «Cursor Plugins (`.cursor-plugin/plugin.json`)» (C21) — показывают цену совместимости приватной обёртки.

**R12. Инструментировать сессии агента traces/metrics/events и включать захват контента отдельно.**
- Доказательство: OTel Copilot отправляет traces (поток сессии, вызовы модели, tool use), metrics (токены) и events (принят/отклонён edit), исключая промпты/ответы/контент инструментов по умолчанию и позволяя админам включать каждый capture class независимо (G15); OTel Cursor только Enterprise, экспортирует tokens/tool calls/cost и lifecycle-логи с opt-in контентом и MCP I/O (C18); Kiro даёт prompt logs, CloudTrail, CloudWatch и CSV (K24).
- Почему изучать: отладка поведения агента требует span-level traces, но захват контента — решение о приватности. Разделение «сколько» и «что сказано» — переиспользуемая механика.
- Что не копировать: делать observability только Enterprise-фичей (C18) или не документировать её вовсе (у нескольких продуктов нет OTel-страницы на проверенных путях). Это оставляет малых клиентов слепыми.

**R13. Поддерживать доверие как гейт на загрузку конфигурации, а не только на исполнение команд.**
- Доказательство: недоверенный workspace Kiro спрашивает перед каждой shell-командой и не загружает custom agents, steering, MCP config или skills (K8); Zed загружает project-local instructions и skills только из доверенных worktree (Z13); `AGENTS.md` Devin инжектится автоматически (W22), но sandbox/permissions гейтуют исполнение.
- Почему изучать: конфигурация, контролируемая репозиторием, — поверхность атаки. Загрузка вредоносного `AGENTS.md`/MCP-конфига до того, как пользователь доверился репозиторию, — supply-chain риск.
- Что не копировать: автозагрузку repository hooks по умолчанию. JetBrains явно игнорирует project-local hooks в `<project>/.junie/config.json` «for safety» и требует `--config-location` для opt-in (J14); это более безопасный дефолт, который стоит изучить.

**R14. Держать объект plan/agent state отдельно от клиента.**
- Доказательство: сессии Copilot «can be shared and resumed across clients» (G1); cloud sessions Kiro живут в cloud session store, все клиенты — «views onto the same session», отключение не останавливает агента, approvals ждут следующего клиента (K19); cloud agents Cursor работают без включённой локальной машины (C6); Agent Command Center Devin сводит локальные и облачные сессии в одном представлении (W14).
- Почему изучать: multi-device continuity — продуктовая возможность, а не фича синхронизации. Переиспользуемая механика — разделение session/attachment с единственным владельцем.
- Что не копировать: заявлять кросс-клиентную непрерывность, оставляя недокументированные клиент-специфичные пробелы (например, матрица возможностей Kiro показывает отсутствие cloud sessions на Mobile в одной строке, K19). Матрица должна быть явной.

**R15. Делать миграцию runtime-фичей, а не маркетинговой страницей.**
- Доказательство: Devin импортирует rules/MCP из восьми инструментов (W24); JetBrains импортирует skills, subagents, MCP-конфиг и guidelines из `.claude`, `.codex`, `.cursor` и предлагает импорт (J6, J7, J13, J16); Copilot читает `.github/skills`, `.claude/skills`, `.agents/skills` плюс `CLAUDE.md`/`GEMINI.md` (G8, G18); Kiro поддерживает Agent Skills standard (K13); Augment использует agentskills.io (A11).
- Почему изучать: стоимость переключения — главный ров этого рынка. Импорт конфигурации конкурента её снижает и принуждает к совместимости форматов.
- Что не копировать: импорт без диагностики конфликтов и правил приоритета. Импорт Devin происходит «automatically» при старте сессии (W24); молчаливые импорты могут маскировать конфликты.

### 6.2. Антипаттерны, которые не стоит копировать

**P1. Противоречивая документация по безопасности.** Страница permissions Trae говорит, что команды агента выполняются в sandbox, а страница Auto-run — что команды «are always auto-run outside the sandbox» (T6 vs T8). Почему не копировать: пользователь не может построить корректную модель угроз, а аудитор провалит продукт только на документации. Одна страница должна владеть моделью исполнения.

**P2. Вероятностное одобрение, поданное как ревью.** Auto-review Cursor по умолчанию использует бэкенд-классификатор и говорит, что он «can make mistakes» и «not a security boundary» (C8). Почему: дефолт, который одновременно вероятностный и назван «review», приглашает к сверхдоверию; если это convenience-гейт, назовите его гейтом и парьте с детерминированными контролями.

**P3. Принуждение, которое молча исчезает на одной поверхности.** Permissions Augment соблюдаются в CLI и Cosmos, но «not enforced in the Augment code extension» (A8). Почему: семантика политики должна быть одинаковой на всех поверхностях, либо поверхность должна быть явно помечена как неуправляемая. Иначе одна установка расширения обходит контроль.

**P4. Непрозрачные ярлыки квот плюс точная цена overage.** Windsurf продаёт «Light/Increased/Significantly higher» квоты, но тарифицирует overage по API list (W20). Почему: клиент несёт риск downside, не зная базового allowance. Публикуйте allowance в единице, которую можно умножить на опубликованную ставку.

**P5. «Unlimited» с обрывом ёмкости.** Junie Lite говорит, что «virtually unlimited describes normal use, not literally uncapped requests», и «there is no downgrade path» при достижении ёмкости (J17); Cursor говорит об отсутствии лимита tool calls, но имеет недельный пул (C2, C14). Почему: «unlimited» должно означать явную fair-use политику с названным fallback, а не нераскрытый потолок с жёсткой остановкой.

**P6. Регионально ограниченные режимы безопасности, раскрытые только сноской.** Automatic Approval в Trae «is not available to users in the United States» (T6). Почему: матрицы возможностей должны быть регионально явными; иначе глобальные команды не могут стандартизироваться.

**P7. Legacy-фичи, документированные как текущие.** Windsurf подробно документирует Cascade и Workflows, хотя Cascade «no longer starts new Cascade conversations», а Devin Local «does not support» Workflows (W10, W12). Почему: пользователи и их автоматизация будут нацелены на мёртвые поверхности. Выводите из эксплуатации или громко помечайте.

**P8. Молчаливое игнорирование конфигурации.** Cursor молча игнорирует обычный `.md` в `.cursor/rules`, потому что в нём нет frontmatter (C4). Почему: молчаливое игнорирование превращает опечатку в отсутствующую политику без ошибки. Минимум — диагностика или команда валидации.

**P9. Платное продолжение той же задачи.** Дефолт в 40 инвокаций legacy Cascade с `continue`, считающимся новым prompt credit (W10). Почему: это превращает технический лимит в биллинговое событие, которое пользователь не может предсказать. Если есть бюджет на задачу, покажите его до задачи, а не как mid-task upsell.

**P10. Несогласованность статуса версии.** Docs Augment говорят «prerelease», а changelog — «first stable release» (A3, A8 vs A15); цены JetBrains расходятся между docs и marketing (J10 vs J20); поддержка skills JetBrains расходится между страницами (J2 vs J13). Почему: несогласованные утверждения о версии/цене/возможностях разрушают доверие и делают enterprise-валидацию невозможной. Один источник истины на факт.

**P11. Дефолтная выгрузка исходников в облако.** Augment загружает workspace в своё облако при включении, с opt-out через ignore-файлы, а не через явное согласие на облачную индексацию (A12); cloud agents Trae хранят репозитории и состояние сессии в облаке (T21). Почему: ожидания «локальной IDE» не выживают при дефолтной облачной выгрузке. Граница данных должна быть first-class выбором со статусом на workspace.

**P12. Связывание телеметрии с личностью без контроля на уровне событий.** Zed привязывает usage к случайному telemetry ID и говорит, что он «may be linked to your [account]» при аутентификации (Z14). Почему: агрегированные метрики защитимы; связь с личностью должна быть отдельным названным выбором.

**P13. Spec-overhead на каждой задаче.** Если workflow принуждает к requirements→design→tasks для правки в одну строку, пользователи обходят его. Сам Kiro ограничивает specs сложными фичами и даёт Quick Spec «without approval gates» (K3); Trae гейтует дефолтный Agent на подтверждении PRD (T2). Почему: процесс должен быть пропорционален; escape hatch — часть дизайна.

**P14. Дробление одного продукта на три пересекающихся без страницы выбора.** JetBrains поставляет AI Assistant, Junie и Air с пересекающимся охватом, разными матрицами фич и разными ценами (J1, J2, J18, J19, J10, J20). Почему: пользователь не может ответить «что мне включить?», а документация противоречит себе. Консолидации нужен явный migration contract.

**P15. Продажа enterprise-контролей до предпосылок.** Zed продаёт Business с RBAC и data governance, пока «SSO, SAML, and SCIM are planned but not currently available» (Z15); у Augment в admin checklist не завершены audit logs и EntraID (A18). Почему: enterprise-покупатели гейтуют по SSO/SCIM/audit в первую очередь; продажа впереди них создаёт провальные пилоты.

**P16. Observability как premium-only возможность.** OTel Export Cursor доступен только Enterprise (C18). Почему: команды, которым отладка поведения агента нужна больше всех, часто находятся в mid-market; базовый trace export должен существовать на нижних тарифах, а захват контента — гейтоваться отдельно.

### 7.2. Что явно не проверено в этом исследовании

- **Ни один продукт не установлен и не запущен.** Все утверждения о runtime-поведении взяты из документации, а не из наблюдения.
- **Ни один бенчмарк не воспроизведён.** Оценки моделей Kiro (K26), заявление Augment о spend/token (A16), «20x faster» Fast Context Windsurf (W8) и «Top performer on SWE-Rebench» JetBrains (J20) — вендорные claims.
- **Ни одна цена не куплена и не выставлена в счёте.** Тарифные таблицы — по публикации на 2026-11-11; налоги, годовые скидки, региональные цены и grandfathered-тарифы не моделировались.
- **Ни один лимит конкурентности или rate limit не протестирован.** Все лимиты — по документации.
- **Ни один контроль безопасности не атакован.** Утверждения «not a boundary» — самооценки вендоров.
- **Тела Trae извлечены из SPA-payload**, а не из серверного текста статьи. Цитируемые предложения — из встроенного JSON документа; часть таблиц в payload пуста, поэтому table-only механики (например, конкретные параметры встроенных инструментов) могут отсутствовать.
- **Заявления JetBrains Air в основном маркетинговые.** Страница Air (J19) и страница Junie (J20) — позиционирование; только там, где утверждение совпадает с docs-страницей (J10, J12, J17, J21), оно трактуется как confirmed.
- **Детали моделей/цен Cursor волатильны.** Переход на The X Subscription, линейка Grok и правила недельного пула менялись в 2026 году несколько раз; любая цифра здесь — снимок на 2026-11-11.
- **Не проверено, реально ли принудительны документированные enterprise-контроли.** MDM-политики, SCIM-провижининг и полнота audit logs прочитаны только в документации; ни один tenant не инспектировался.
