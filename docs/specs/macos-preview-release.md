# macOS Preview prerelease without Apple signing credentials

## Product contract

An explicitly requested macOS Preview prerelease may be built on a developer's Mac and published to the existing GitHub repository without Developer ID or notarization credentials. It uses the isolated `ZCode Preview` identity, bundle ID `dev.zcode.app.preview`, and a valid space-free Preview executable name; the `.app` display name remains `ZCode Preview`. Build-time bundle and `app.asar` paths must derive from the same platform executable identity that electron-builder uses (`ZCodePreview.app` for Preview), while Finder display name and release artifact names retain `ZCode Preview`.

This Preview is an offline ZCode-service build. It does not require an account or a test backend. Every compiled ZCode backend origin used by Desktop main, Host, services, and renderer resolves to `http://127.0.0.1:0`, an unavailable loopback endpoint. Offline Preview must also avoid automatic or user-triggered requests to ZCode-owned production CDNs: the official catalog and its assets may be shown from an existing local cache or bundled data, but refreshes and downloads that require `cdn-zcode.z.ai` or `cdn.codegeex.cn/zcode` are unavailable. Built-in plugins and explicitly configured personal marketplace sources keep their existing behavior. ZCode-owned CDN images use a local fallback rather than making an image request. Account-dependent Rewards navigation is disabled in this build so it cannot open the public ZCode site. ZCode telemetry and automatic update checks are disabled. This does not disable user-configured external model providers or the local OpenCode CLI provider. Preview release notes must say that ZCode account/backend and official-CDN-dependent features are unavailable in this build; the endpoint can be configured later when the user's own service exists. Shell and `.env` values must not redirect this build to a public ZCode origin. The GitHub assets must carry the `_TEST` suffix, be marked as a prerelease, and state clearly that Gatekeeper may block first launch until the user approves it. It must never be represented as a signed/notarized production release or overwrite the stable release channel.

## Release owner and sequence

The local release script owns version bumping, build, push, GitHub release creation, and post-publication verification. It keeps `package.json`, root `package-lock.json` top-level version, and `package-lock.json` root package version synchronized. Sequence: require a clean `dev` checkout at `origin/dev` → force the offline-preview build flag and pin all compiled ZCode endpoint aliases to the loopback endpoint → disable signing → bump patch/minor/major → build `ZCode Preview` for current Mac architecture → verify the executable-derived app bundle name, exact app version, architecture, bundle identity, offline endpoint, `_TEST` artifact names, archive contents, and hashes → Russian version commit → push `dev` → create a GitHub prerelease pinned to that commit → download the release files and compare hashes and tag target. GitHub's observed release API representation replaces spaces in uploaded asset basenames with dots; metadata and downloaded files are mapped back to the exact local asset pair before their SHA-256 values are compared.

If the push succeeds but release creation or verification fails, rerun `pnpm release:macos:preview:resume <version>` with the exact version printed by the failed run. Resume requires a clean `dev` checkout whose `HEAD` equals `origin/dev`, a commit whose only changed files are `package.json` and `package-lock.json`, synchronized root versions matching the requested version, the matching Russian Preview version commit, the same explicit test endpoint, and the already-built local assets. It never bumps or commits again. Both GitHub's HTTP 404 and the `gh release view` CLI response `release not found` mean that no release exists; other errors remain fatal. An existing tag or release is accepted only when it resolves to that exact commit; a matching complete prerelease is reverified idempotently. If GitHub contains a draft, incomplete release, or release with mismatched metadata/assets, resume stops without publishing or modifying it; inspect and repair or delete that release in GitHub before retrying.

The GitHub token is used only by `gh` for the user's authorized `dev` push and prerelease creation. No Apple credentials are read, inferred, printed, or required. A failed pre-publication gate leaves no release; a failed post-publication verification reports the release URL and failed claim without claiming success.

## Evidence and limitations

The process proves that the exact commit was pushed, that the local Preview app and archives passed structural/version/architecture checks, and that downloaded release assets match local SHA-256. It does not prove Apple signing/notarization, Gatekeeper acceptance, compatibility on other Mac hardware, provider authentication, runtime quality, or PRISM self-improvement. Release notes must state the backend environment. Cross-platform installers require separate Windows/Linux builds and evidence.

## Acceptance scenarios

| ID          | Scenario                                                                                                    | Required result                                                                                                                                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| PREVIEW-01  | No Developer ID, no Apple notarization credentials                                                          | Preview build proceeds with signing disabled and does not inspect secrets.                                                                                                                                         |
| PREVIEW-01a | No test endpoint is configured                                                                              | Build uses the unavailable loopback endpoint for all compiled ZCode backend aliases; no account/test service is required.                                                                                          |
| PREVIEW-01b | Version commit is prepared                                                                                  | package.json and both root package-lock.json version fields equal the release version.                                                                                                                             |
| PREVIEW-02  | Preview artifact identity                                                                                   | App is `ZCode Preview`, bundle ID differs from stable, executable name is valid and space-free, loopback backend is selected in main and renderer, `_TEST` asset suffix, exact version/architecture are validated. |
| PREVIEW-02a | User shell or `.env` attempts to set a public ZCode endpoint                                                | Build overrides every ZCode endpoint alias and compiled default to loopback; inspectable packaged main and renderer contain no public ZCode backend destination.                                                   |
| PREVIEW-02b | User selects the local OpenCode CLI provider or a custom external model provider                            | Local OpenCode CLI and user-configured external providers remain available; their endpoints are not rewritten to the ZCode loopback sink.                                                                          |
| PREVIEW-02c | Private build defaults provide telemetry or automatic-update endpoints                                      | Preview explicitly disables ZCode RUM, telemetry, and automatic update checks and does not embed packaged-agent OTLP credentials.                                                                                  |
| PREVIEW-02d | A draft chat renders suggested icons, or the user opens/refreshes/installs from the official plugin catalog | No request is made to ZCode-owned CDN hosts; cached/bundled metadata and built-in plugins remain usable, and CDN-dependent operations fail with a local Preview explanation.                                       |
| PREVIEW-03  | Archive validation                                                                                          | DMG and ZIP contain only the expected Preview app and match its payload hash.                                                                                                                                      |
| PREVIEW-04  | Release publication                                                                                         | Versioned tag targets the exact pushed `dev` commit, GitHub marks release prerelease, assets have Preview names, downloaded SHA-256 equals local output.                                                           |
| PREVIEW-05  | Invalid branch, dirty tree, stale origin, mismatched tag, malformed assets, failed build, or missing auth   | Stop before publishing; do not alter `main`; do not report release success.                                                                                                                                        |
| PREVIEW-05a | Release creation fails after `dev` push                                                                     | Resume the exact pushed version commit without another version bump; reject a tag/release targeting another commit.                                                                                                |
| PREVIEW-06  | UI/download instructions                                                                                    | Release notes identify unsigned/unnotarized status and explain first launch approval in plain language.                                                                                                            |
