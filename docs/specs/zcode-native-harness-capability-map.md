# ZCode native harness capability map

## Scope and method

This map compares the checked-in source catalog at `../.cursor-dev` with the current ZCode CLI/runtime source. It records every source agent, rule, and skill entrypoint found in the sibling catalog. Paths in the tables are relative to the ZCode repository root unless the `Source` column says otherwise.

The dispositions mean:

- **native** — ZCode already owns the behavior in its runtime or always-bundled harness pack.
- **adapt** — the portable behavior is represented by a ZCode-owned adaptation; the source implementation or host-specific assumptions are not reused.
- **reuse-plugin** — the capability is supplied by an installable/feature plugin. It is available in ZCode, but is not an always-bundled harness resource.
- **exclude** — the source behavior is deliberately not transferred, with the reason recorded in the row.

An adjacent repository skill, a Cursor folder, or a similar filename is not a ZCode product equivalent. Repo-local developer instructions under `.agents/skills/` are not packaged runtime skills. A product-plugin owner is identified as **plugin**, not **always-bundled**. The runtime must continue to work with empty HOME and without Cursor or the sibling source repository.

## Explicit gaps carried by the source-to-native spec

Crash-injection Desktop E2E `conversation-session-swarm-crash` is the acceptance for Swarm restart boundaries (graph commit, child reservation, child execution, root synthesis). When recovery marks a child attempt completed from `lastOutcome`, an empty node result receives only the last assistant reply text, capped at 4000 characters. Tool output, reasoning, and user prompts stay in the child session and are not copied into the journal or the root transcript. Shared evaluation cases are owned by `.zcode/evaluation-cases.json` and `parseSharedEvaluationCatalog`; `/evaluate` reports each accepted case as pass, fail, or not run, and an invalid or escaped catalog is not a passed suite. Evidence-gated lesson capture after a completed local turn is owned by `persistent-memory`: a same-tool failure then success writes one knowledge-curator lesson and index line without copying tool output or error messages. Large generic MCP text results are paged by `apps/zcode-cli/packages/core/src/mcp/index.ts`: the first page is returned immediately, and a later call with only the stored page fields reads another page without a server call. Replay of the same accepted Swarm input continues only never-started nodes whose dependencies are already completed. ZCode now has durable run/node facts plus restart reconciliation both on the next root Swarm input and on cold chat open (`resumeFromStore`): takeover increments `ownerEpoch`, in-flight attempts without child `lastOutcome=completed` become `interrupted` and are not redispatched, and `SwarmRunUpdated` is re-projected from the journal without a model call. A different `sourceCommandId` still interrupts the old run. See `docs/specs/zcode-swarm-mode.md`; neither the process-local SessionEventStore nor Host task index claims journal ownership. Profile authoring, validation, roots, and hash-guarded interrupted-rename recovery are ZCode-owned and do not depend on `.cursor`; see `docs/specs/zcode-agent-profile-lifecycle.md`. The always-bundled pack now includes ZCode-owned codebase design, document co-authoring, visual-reference UI implementation, and stronger frontend craft alongside the existing handoff, performance, MCP authoring, research, domain modeling, and merge conflict procedures. Handoff notes do not claim automatic mission resume, and a skill source in the worktree does not by itself prove Desktop/SEA/remote release inclusion; those require the spec's package-parity and acceptance checks. The rows above add further optional domain skills whose disposition must remain explicit. Do not mark a gap implemented solely because an agent prompt mentions it or a plugin can access a tool related to it.
