# Группировка MCP-реестра по capability family

Статус: реализовано 2026-11-15.

## Проблема

Официальный MCP Registry содержит много независимых реализаций одной функции: например,
пять filesystem-серверов от разных авторов с разными npm-пакетами. Дедуп по package/endpoint
их не схлопывает, и список «Все» превращается в стену похожих карточек.

## Продуктовое правило

1. В списке реестра показывается одна карточка на capability family: `filesystem`,
   `playwright`, `github`, `slack`, `postgres` и т.п. Остальные реализации скрыты.
2. Карточка помечается `N похожих`; кнопка «Показать похожие»/«Скрыть похожие»
   переключает полный список.
3. Внутри family выбирается лучший кандидат: curated/редакционный выше обычного,
   при равенстве — текущий порядок сортировки.
4. Family определяется детерминированно по имени сервера: последний сегмент id,
   нормализация `mcp/server/tool/api` и известные capability-ключевые слова.
5. Дедуп по npm package/https endpoint остаётся первым слоем; grouping — второй.
6. Поиск сохраняет grouping: пользователь видит одну карточку family и может раскрыть
   альтернативы.

## До / после

| Сценарий | До | После |
| --- | --- | --- |
| 5 filesystem-серверов | 5 карточек | 1 карточка + «4 похожих» |
| Раскрыть alternatives | — | кнопка «Показать похожие» |
| Разные capability | все видны | по одной карточке на family |
