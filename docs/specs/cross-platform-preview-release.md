# Cross-platform Preview release

## Product contract

`.github/workflows/cross-platform-preview-release.yml` is manual-dispatch only. It publishes an unsigned Preview prerelease for the exact version tag named in its required `release_tag` string input. A version tag push, a branch push, or a pull request starts no workflow run. Manual dispatch checks out and builds the source at that tag, even when the workflow definition is invoked from `dev`. While GitHub Actions billing is unavailable, the local macOS Preview release script (`mise exec -- pnpm release:macos:preview`, see `macos-preview-release.md`) is the canonical release path that produces the macOS Desktop artifact; Windows and Linux installers remain unavailable until billing is restored. The workflow builds the Desktop application and standalone CLI for macOS Apple Silicon (`darwin-arm64`), Windows x64 (`win-x64`), and Linux AMD64 (`linux-x64`). Desktop uses the existing offline Preview contract: ZCode-owned backend origins resolve to unavailable loopback, ZCode telemetry and automatic updates are disabled, and no ZCode account is required. User-configured model providers and the local OpenCode CLI keep their normal behavior. The packages are Preview builds, not production builds.

Desktop outputs are macOS DMG and ZIP, Windows NSIS installer, and Linux AppImage, DEB, RPM, and pacman package. CLI outputs are standalone SEA executables for all three targets. Artifacts include the release version and platform/architecture in their names. The release is marked prerelease and its notes state that the macOS build is unsigned and may require first-launch approval.

## Ownership and sequence

The repository owns the build contract and tag/version agreement. Only an explicit manual dispatch naming an existing `vMAJOR.MINOR.PATCH` tag starts the workflow, with read-only contents permission for build jobs; only the final publish job receives `contents: write`. No push event (tag or branch) and no pull request starts it, so the tag created by the local macOS release cannot produce a hosted run. Each Desktop target builds on its native runner. Each CLI target builds on a native runner and smoke-tests its executable. Build jobs upload artifacts; the publish job downloads and validates the complete platform asset set before publication. It creates a prerelease if none exists, or appends/replaces the validated assets on an existing prerelease when its version tag points at the same commit. It refuses to modify a stable release or a release for a different commit. This makes retries and adding non-Mac artifacts to a locally published Mac prerelease safe.

The local macOS release script owns version bumping, build, push, prerelease creation, and post-publication verification for the macOS Desktop app; its sequence and acceptance scenarios live in `macos-preview-release.md`.

The workflow does not bump versions or push commits. Before dispatch, the release version in the root package manifest at the requested tag must match the tag. Missing signing credentials do not block Preview: macOS signing/notarization remain disabled. A failed build or missing platform output prevents publication.

## Evidence and limitations

Acceptance of the workflow contract requires that a version tag push, branch push, or pull request starts no run, and that a manual dispatch with `release_tag` passes all three Desktop and CLI build jobs, attaches the expected artifacts to the prerelease, and points the release at the tagged commit. Acceptance of the canonical local path requires a successful `mise exec -- pnpm release:macos:preview` run, which produces the unsigned macOS Desktop app and its `_TEST` prerelease assets as described in `macos-preview-release.md`. These checks prove builds and publication, not runtime behavior on every OS/device, Apple notarization, external provider availability, or production-backend readiness. While GitHub Actions billing is unavailable, no workflow run can supply evidence and Windows/Linux installers stay unshipped. The workflow consumes GitHub-hosted runner minutes; GitHub billing and runner availability remain external requirements.

## Acceptance scenarios

| ID          | Scenario                                                                               | Required result                                                                                                                                                                                                        |
| ----------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| XPREVIEW-01 | Push a version tag, push a branch, open a pull request, or dispatch with `release_tag` | No workflow starts for any push or pull request; a manual dispatch with `release_tag` builds and publishes all targets; the local macOS Preview release produces the Desktop app while Actions billing is unavailable. |
| XPREVIEW-02 | Build Desktop targets                                                                  | macOS arm64, Windows x64, and Linux x64 each produce the formats listed above.                                                                                                                                         |
| XPREVIEW-03 | Build CLI targets                                                                      | macOS arm64, Windows x64, and Linux x64 standalone executables are generated and smoke-tested.                                                                                                                         |
| XPREVIEW-04 | No Apple signing credentials                                                           | Unsigned macOS Preview packages build and release notes explain first launch approval.                                                                                                                                 |
| XPREVIEW-05 | Publish when no release exists                                                         | One prerelease points to the exact tag commit and contains all expected versioned artifacts.                                                                                                                           |
| XPREVIEW-08 | Publish when a same-tag prerelease already exists                                      | The complete validated asset set is added idempotently to that prerelease without creating a duplicate release.                                                                                                        |
| XPREVIEW-09 | Existing tag points to a stable release or another commit                              | Publication stops before uploading assets or editing the release.                                                                                                                                                      |
| XPREVIEW-06 | A target fails or an artifact is missing                                               | The publish job does not create a partial release.                                                                                                                                                                     |
| XPREVIEW-07 | Requested release tag and root package version differ                                  | The manual dispatch fails before building.                                                                                                                                                                             |
