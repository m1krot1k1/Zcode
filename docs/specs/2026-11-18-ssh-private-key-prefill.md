# Предзаполнение SSH-ключа при новом подключении

> Статус: реализовано 2026-11-18.

## 1. Проблема

При добавлении нового SSH-сервера форма всегда открывалась с пустым
`privateKeyPath`, хотя этот же ключ уже использовался в предыдущих сессиях.
Пользователь заново выбирал файл или вводил путь вручную.

## 2. Контракт

1. Источник — история remote workspace-сессий
   (`buildSshConnectionHistorySuggestions(remoteWorkspaceSessions).privateKeyPaths`),
   первый (самый свежий) путь.
2. Предзаполнение выполняется только когда одновременно:
   - диалог открыт;
   - текущий шаг — `settings`;
   - выбран `kind=ssh`;
   - нет `preferredProfileId`, выбранного `sshConfigAlias` и уже введённого
     `privateKeyPath`.
3. Если поле аутентификации стоит на `password` и пароль ещё пуст, форма
   переключается на `privateKey`. Если пароль уже введён, способ
   аутентификации не меняется.
4. Если пользователь очистил поле вручную, повторно значение не
   навязывается в рамках того же открытия диалога.
5. Переключение на другой `kind` сбрасывает флаг применения: при возврате на
   SSH путь снова доступен для предзаполнения.

Порядок важен: на странице выбора «新建 SSH 连接»/«New SSH connection»
сначала вызывает `resetDraft()`, затем переходит на шаг `settings`. Если
записать ключ до `resetDraft`, значение будет затёрто — это и было причиной
пустого поля в первом варианте реализации.

## 3. Границы

- Пароли и passphrase не сохраняются и не предзаполняются.
- История читается только из уже загруженных `remoteWorkspaceSessions`; новых
  запросов к диску или сети нет.
- Явно выбранный профиль, alias или введённый ключ всегда приоритетнее
  истории.
