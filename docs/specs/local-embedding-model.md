# Local embedding model

Status: active (2026-11-22, release 3.17.153)

The code index already supports Ollama and OpenAI-compatible embedding providers. This
spec adds a **managed local path**: the Host can download the local runtime, pull a
recommended embedding model, start it, and select the model for the workspace without the
user installing a separate server manually.

## Ownership

| Layer                    | Owner                                                              | Responsibility                                                    |
| ------------------------ | ------------------------------------------------------------------ | ----------------------------------------------------------------- |
| Runtime download/extract | `packages/services/src/code-intelligence/localEmbeddingRuntime.ts` | Fixed GitHub release asset, platform archive, managed tools root  |
| Process lifecycle        | same module                                                        | Start/probe `ollama serve`, kill only the child it started        |
| Model pull               | same module                                                        | `ollama pull`, bounded output, model-name validation              |
| Workspace config         | `codeIntelligenceService.setEmbeddingConfig`                       | Existing Ollama endpoint/model persistence; no new secret path    |
| UI                       | `packages/ui/src/agent-workbench/EmbeddingProviderSettings.tsx`    | Install/pull/use actions, status, failure text                    |
| Index/search             | existing worker embedding plan                                     | No change: vectors are still generated by the configured provider |

The managed runtime lives under `{dataRoot}/.zcode/tools/local-embeddings`; it is not
bundled into the DMG. The model is cached by Ollama under the same tools root. Deleting
the tools root removes both runtime and models.

## Recommendation

The recommendation is deterministic from total system RAM:

- **< 24 GB RAM:** `nomic-embed-text` (768 dimensions, about 274 MB). Chosen for the best
  quality/size trade-off on code and mixed documentation.
- **>= 24 GB RAM:** `bge-m3` (1024 dimensions, about 1.2 GB). Chosen for multilingual
  retrieval, including Russian.

The UI shows the recommended model, dimensions, download size, and the reason. The user
can still use a different Ollama model through the existing free-form fields.

## Flow

1. `getLocalEmbeddingStatus()` detects a managed or system `ollama` binary, its version,
   whether the local server is running, installed model names, and the recommendation.
2. `installLocalEmbedding()` downloads the platform release asset
   (`ollama-darwin.tgz`, `ollama-linux-{arch}.tar.zst`, or
   `ollama-windows-{arch}.zip`), extracts it into the managed tools root, verifies
   `ollama --version`, and is idempotent. A system binary is used as-is.
3. `pullLocalEmbeddingModel({ model })` validates the model name, starts the local server
   if needed, runs `ollama pull` with a bounded timeout, and verifies the model appears in
   `/api/tags`.
4. The UI saves `provider: "ollama"`, `endpoint: "http://127.0.0.1:11434/api/embed"`, and
   the model through `setEmbeddingConfig`. The existing embedding phase then builds
   vectors on the next index pass.
5. "Use model" selects an already installed model without downloading.

## Security and failure rules

- Model names are limited to `[a-zA-Z0-9._:-]` segments with at most one `/` and no `..`;
  arguments are passed as an argv array, never a shell string.
- Download URLs are fixed to the official Ollama GitHub release path; no user URL is
  accepted by the managed installer.
- Command output is bounded; diagnostics shown to the user are truncated.
- The Host only kills the `ollama serve` child it started. An already running local
  server is reused and left alone.
- Failure is explicit: `runtime-missing`, `runtime-start-failed`, `download-timeout`,
  `download-failed`, `model-not-listed`, `invalid-model-name`, or
  `local-embedding-runtime-unsupported:<platform>/<arch>`.
- No embedding vector or API key is written to the index; the existing credential rules
  remain unchanged.

## Acceptance

- On a clean machine, the embedding settings show "Runtime not installed" and the
  recommended model, without blocking the manual Ollama/OpenAI-compatible form.
- Install is idempotent and reports the detected version.
- A successful model pull saves the Ollama config and the status becomes ready after the
  next index pass.
- Unsafe model names and unsupported platforms fail before any process spawn.
- The runtime works on macOS, Linux, and Windows archive layouts; Windows uses
  `Expand-Archive`, macOS/Linux use `tar`.
