# Долговременный аудит решений о разрешениях

Статус: спецификация (реализация — в этой же ветке).

## Проблема

Сейчас решение «разрешить/запретить инструмент» живёт только в памяти и в UI-событиях.
После перезапуска нельзя доказать, кто и по какому правилу одобрил действие: в
durable-пути `apps/zcode-cli/packages/core/src/runtime/methods/events.ts` есть
`TurnComplete/TurnError`, checkpoint, rewind, auto-resolution и PRISM-факты, но нет
записи о решении по разрешению. Для разбора инцидентов и корпоративных требований это
блокер.

## Контракт

Новый тип записи: `runtime/permission_decision` в `SessionEntryType`
(`apps/zcode-cli/packages/contracts/src/interfaces/session-store.port.ts`).

Полезная нагрузка (append-only, без текста команды и секретов):

| Поле         | Тип                                         | Смысл                                  |
| ------------ | ------------------------------------------- | -------------------------------------- |
| `schema`     | `"zcode.permission.decision.v1"`            | версия схемы                           |
| `decisionId` | string                                      | стабильный id, идемпотентность повтора |
| `sessionId`  | SessionId                                   | сессия-владелец                        |
| `turnId`     | TurnId                                      | ход                                    |
| `toolCallId` | string                                      | конкретный вызов                       |
| `toolName`   | string                                      | имя инструмента                        |
| `decision`   | `allow` \| `deny` \| `escalate` \| `modify` | результат                              |
| `source`     | `policy` \| `auto` \| `user` \| `hard_deny` | кто принял решение                     |
| `reasonCode` | string                                      | стабильный код причины, не текст       |
| `ruleId`     | string?                                     | id правила политики, если применимо    |
| `traceId`    | string                                      | трассировка                            |
| `createdAt`  | number                                      | время                                  |

Ограничения: строка ≤ 2 КиБ; `toolName`/`ruleId` ≤ 120 символов; никаких `command`,
`args`, путей и пользовательского текста. Одно решение — одна запись; повтор с тем же
`decisionId` и телом игнорируется, конфликтующий повтор отклоняется.

## Владелец и порядок

- Единственный владелец — `AgentRuntime` (тот же durable-путь, что для остальных
  SessionEntry). Renderer и Host не пишут аудит.
- Запись выполняется после финального решения и до возврата управления
  исполнителю инструмента, чтобы разрешённое действие не могло произойти без следа.
- Ошибка записи не превращает разрешение в отказ (пользователь уже принял решение), но
  добавляет `warn` с `event: permission_decision.persist_failed` и не считается
  доказанным аудитом.

## Проверки

- unit: allow/deny/hard-deny создают ровно одну запись с ожидаемыми полями;
- unit: повтор `decisionId` идемпотентен, конфликт отклоняется;
- unit: в запись не попадают текст команды/аргументы;
- integration: после cold resume запись читается из SessionStore.

## Что не входит

- Экспорт аудита в внешний SIEM.
- UI-просмотр журнала решений (отдельная задача).
