# Установка локального OpenCode CLI из IDE

## Продуктовый контракт

- ZCode запускает установленный OpenCode CLI на том Host, которому принадлежит workspace; Renderer не запускает системные команды.
- До установки Host повторно обнаруживает CLI. Существующая рабочая установка не обновляется и не заменяется.
- Установка начинается только после подтверждения в UI. Она не запускает модель, не переносит credentials и не меняет настройки OpenCode.
- macOS и Linux используют официальный OpenCode V2 installer (`https://opencode.ai/v2/install`) во временном `HOME`, затем копируют проверенный бинарник в пользовательскую `~/.opencode/bin` с exclusive-create. Установка не требует системного `npm` и не редактирует shell-профили: передаётся `--no-modify-path`.
- Windows использует официальный пакет WinGet `Anomaly.OpenCode`; согласия источника и пакета принимаются только после UI-подтверждения, а `--no-upgrade` запрещает замену уже установленного CLI.
- После установки Host заново разрешает путь и проверяет `opencode --version`. Реальный ACP handshake проверяется при явном старте сессии; installation probe не создаёт сессию и не обращается к модели.
- Если необходимые штатные инструменты платформы недоступны, UI показывает ручную инструкцию вместо кнопки, которая заведомо завершится ошибкой.
- Ошибки установки передаются UI только через закрытый набор безопасных диагностик: ошибка загрузки, некорректный/неполный installer, ошибка запуска installer/package manager, timeout, конфликт уже занятого destination, ошибка post-install verification и неподдерживаемый способ установки. Raw stderr, команды, абсолютные пути, переменные окружения и credentials не пересекают Host/RPC границу и не показываются в UI.
- Доступность Install сейчас зависит от установочных инструментов Host (`bash` + `curl` для macOS/Linux; WinGet для Windows). Это известное ограничение, а не выполнение требования «установка на любой поддерживаемой ОС». Для полного выполнения требования нужен проверяемый Host-owned fallback, который не зависит от этих инструментов; он не должен активироваться по динамическому URL без проверяемого digest и подтверждённого ACP handshake.

```text
UI: явное подтверждение
  → window-scoped Local Host: повторное обнаружение CLI
  → официальный installer платформы (без shell interpolation)
  → повторное обнаружение + --version
  → пользователь явно запускает сессию
  → `opencode acp` initialize / newSession
  → модельный запрос только после явного prompt
```

## Критерии приёмки

| ID    | Сценарий                                                        | Приёмка                                                                                                                                                                                                                         |
| ----- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OI-01 | macOS/Linux без CLI, с доступными `bash` и `curl`               | UI предлагает установку; команда использует официальный V2 script, user-owned install dir и `--no-modify-path`; после неё бинарник найден и версия проверена.                                                                   |
| OI-02 | Windows без CLI и с WinGet                                      | Используется native `winget.exe` и точный официальный package ID; соглашения принимаются лишь после UI-confirm; install не обновляет найденный CLI.                                                                             |
| OI-03 | CLI уже доступен или выбран явный путь                          | Installer не запускается и не заменяет файл; статус возвращает найденную версию.                                                                                                                                                |
| OI-04 | Installer, сеть или проверка версии завершаются ошибкой/timeout | Дерево процессов завершается; UI получает точную локализованную диагностику из закрытого allowlist (`install-download-failed`, `install-script-invalid`, `install-execution-failed`, `install-package-manager-failed`, `install-timeout`, `install-destination-conflict`, `install-verification-failed`); raw stderr, пути, команды и секреты не раскрываются, успешный статус не выставляется. |
| OI-05 | После установки пользователь запускает OpenCode                 | ACP handshake и список моделей получаются от установленного CLI на workspace Host; API-key provider остаётся отдельным режимом.                                                                                                 |
| OI-06 | Проверка установки                                              | Никакой session/prompt/model request не выполняется, provider rate limit не обходится и credentials не читаются/копируются кодом ZCode.                                                                                         |
| OI-07 | `bundle:desktop` создаёт packaged app                           | Финальный `app.asar` содержит достижимые Host chunks OpenCode resolver/installer и renderer chunks OpenCode settings panel. Bundle gate проверяет маркеры обеих графов и останавливает выпуск, если отсутствует runtime или UI. |
| OI-08 | Host не имеет `bash`/`curl` или WinGet                           | UI не обещает успешную установку и объясняет ограничение. Это не считается универсальной установкой; требование закрывается только после добавления проверенного fallback для соответствующей ОС/архитектуры и реального ACP smoke. |

## Независимые доказательства

- Unit-тесты подтверждают точные argv, безопасную передачу среды, повторное обнаружение и отказы на каждой платформе.
- На macOS выполняется безмодельный smoke настоящего установленного бинарника: version, ACP initialize и config options; prompt не отправляется.
- Bundle gate анализирует финальный `app.asar` после electron-builder: проходит JavaScript import graph от Host entry и renderer HTML entry и требует маркеры официального installer, CLI diagnostics и settings panel. Регрессионный тест проверяет полный bundle и отсутствие runtime/UI chunks.
- Windows и Linux остаются подтверждёнными контрактными тестами, пока нет соответствующих физических/виртуальных платформенных runner-ов; это не эквивалентно живому системному установщику.
