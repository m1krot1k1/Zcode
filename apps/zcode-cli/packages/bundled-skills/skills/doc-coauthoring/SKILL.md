# Document co-authoring

Help the user produce a document that serves its audience and purpose. Keep the process collaborative without forcing a long interview: use context already supplied, ask only questions whose answers change the document materially, and let the user choose a complete draft or an iterative section-by-section process.

## 1. Establish purpose and constraints

- Identify the document type, primary reader, decision or action it should support, and any required template, length, tone, or deadline.
- Gather the user's background, source files, constraints, alternatives, prior decisions, and open questions from the conversation and supplied material.
- Separate verified facts, user-reported context, assumptions, and unknowns. Never invent citations, stakeholder positions, data, or approval.
- Ask concise clarifying questions only for gaps that materially affect correctness or structure. If the user has supplied enough context, proceed with a short statement of assumptions.

## 2. Propose a structure

- Choose an outline suited to the actual document, rather than applying a fixed template to every request.
- For a specification or proposal, consider purpose, current behavior, goals and non-goals, proposed behavior, ownership, alternatives, risks, migration, and acceptance evidence as relevant.
- For a decision record, make the decision, context, options, trade-offs, and consequences easy to find.
- For a plan, connect each deliverable to an owner, dependency, and observable completion condition.
- Show the outline before drafting only when the user asked to collaborate, the structure is uncertain, or the document is substantial enough that a wrong outline would waste work. Otherwise draft directly.

## 3. Draft and refine

- Write for the intended reader. Define necessary terms, put the main conclusion early, and keep one idea per section.
- Preserve the user's intended decisions and wording where practical. Do not silently resolve an open product or technical choice.
- Keep evidence and recommendations distinct. Link supplied references when available and qualify claims that cannot be checked.
- Revise surgically from feedback. When editing a file, preserve unrelated sections and existing conventions.

## 4. Review as a new reader

Read the finished document without relying on the conversation. Check whether the audience can identify the purpose, decisions, required actions, definitions, evidence, and unresolved questions. Look for contradictions, missing acceptance criteria, unexplained jargon, unsupported claims, and sections that repeat the same point.

If the requested format is an editable document, use the application's existing document capability or plugin. This skill defines the writing process; it does not assume a specific external connector, document editor, or file-generation tool.
