# Task planning

1. Restate the requested outcome, scope, constraints, and authorization already given. Ask only about a fact that blocks safe progress.
2. Separate the work into deliverables. A branch is independent only if it can produce useful evidence without waiting for another branch or editing the same ownership area.
3. For each branch, name one exact available role, its deliverable, relevant source context, dependencies, and acceptance evidence.
4. Keep the plan proportional. Answer-only and small tasks stay direct; do not decompose a single capability probe into duplicate agents.
5. Preserve existing local changes and identify release, external-service, or runtime evidence that is outside the current execution environment.
6. Start work after planning when the user has authorized implementation. Do not present the plan as completed work.
