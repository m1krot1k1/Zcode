# cli-exec-pty

Модуль даёт агенту интерактивные терминальные сессии поверх `node-pty`. Владелец
состояния — `AgentPtyManager`: он единственный держит дескрипторы PTY, таймеры
простоя и кольцевые буферы. Наружу отдаются только снимки (`PtySessionInfo`).

## Инварианты

1. **Инкрементальное чтение без потерь и дублей.** Каждый чанк получает монотонный
   `seq`. `read({ sinceSeq })` возвращает строго `seq > sinceSeq`. Если запрошенная
   позиция уже вытеснена из буфера, возвращается `truncatedFrom` — потеря видима,
   а не маскируется.
2. **ANSI разбирается, а не выбрасывается.** `parseAnsi` распознаёт CSI/OSC/двухбайтные
   последовательности по ECMA-48 и переносит незавершённый хвост (`ESC [` в конце
   чанка) в следующий вызов. Именно это переживает разрезанный между `onData` SGR.
3. **Буфер ограничен.** Бюджет по умолчанию — 1 МиБ на сессию. При переполнении
   вытесняются старые чанки; `truncatedBytes` и `firstSeq` показывают масштаб потери.
4. **Песочница общая с Bash.** Внутри PTY запускается обёрнутый shell (`bwrap`/
   `seatbelt`/`degraded`); `sandboxMode` присутствует в каждом снимке.
5. **Уничтожение гарантировано.** `kill()` сначала снимает дерево по PGID через
   `cli-exec-sandbox.killTree`, затем закрывает дескриптор PTY. `dispose()` делает
   то же для всех сессий и снимает таймеры, поэтому после него не остаётся живых
   дескрипторов.
6. **Ограничение количества.** `maxSessions` (по умолчанию 4) проверяется в `create()`
   до spawn; завершённые сессии вытесняются автоматически.
7. **Идемпотентность гонок.** `write()`/`resize()` на завершённой сессии — no-op:
   агент пишет в гонке с `exit`, и это не должно валить инструмент.
8. **Простой закрывается сам.** `idleTimeoutMs` (по умолчанию 10 мин) убивает
   забытую сессию, чтобы не течь дескрипторами.

## Рантайм и упаковка

- `node-pty` загружается лениво при первом `create()`. Команды, которым PTY не нужен
  (`app-server --prepare-storage`, обычный старт CLI без вызова `PtySession`), не
  должны падать из-за отсутствующего нативного аддона.
- В упакованном desktop приложении `zcode.cjs` исполняется из `resources/glm`, поэтому
  резолв не видит `app.asar.unpacked`. Пакет обязан лежать рядом:
  `resources/glm/node_modules/node-pty` с `prebuilds/<platform>/pty.node`.
- Отсутствие `node-pty` при первом `create()` — ошибка инструмента `PtySession`,
  а не отказ запуска приложения.

## Пересечения

- `cli-exec-sandbox`: политика изоляции и `killTree`. Без него модуль не собирается.
- Инструмент `PtySession` в `core`: единственный потребитель; он же отвечает за
  маппинг действий (`start`/`write`/`read`/`wait`/`resize`/`kill`/`list`) в методы.
