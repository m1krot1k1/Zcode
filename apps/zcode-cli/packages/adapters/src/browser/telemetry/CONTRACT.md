# cli-browser-telemetry

Модуль собирает телеметрию браузерных действий и отдаёт её **модели** в результате
инструмента. Владелец состояния — `BrowserTelemetryController`: только он держит
подписки Playwright на живую `Page` и буфер текущего окна наблюдения.

## Инварианты

1. **Подписка одна на страницу.** `attach(page)` идемпотентен; повторный вызов не
   создаёт дубликаты слушателей. `detach(page)` снимает всё, включая таймер диалога.
2. **Окно наблюдения атомарно.** `beginAction(page)` очищает буфер страницы, поэтому
   `observe()` содержит только эффекты одного действия — без «наследства» предыдущих.
3. **Диалог не залипает.** При `dialogPolicy: "record"` незакрытый диалог закрывается
   по `dialogAutoDismissMs` с явной пометкой `auto_dismissed`. При `auto-dismiss`
   закрывается сразу. `noteDialogHandled()` снимает таймер, когда агент ответил сам.
4. **Бюджеты явны.** Каждый массив ограничен (`BROWSER_OBSERVATION_BUDGETS`), а
   `truncation` содержит флаг усечения для каждого источника. Потеря данных видима.
5. **Здоровье по фактам.** `healthy` = нет `pageerror`, нет `console.error`, нет
   `requestfailed` и нет 5xx. Оно не выводится из `ok` команды.
6. **Тела ошибок ограничены.** Для ответов >= 400 читаются первые
   `maxResponseBodyBytes` байт; недоступное тело не считается ошибкой модуля.
7. **Кадр не бесплатен.** JPEG прикладывается при нездоровом состоянии или по
   `includeScreenshot`; кадр сверх `maxScreenshotBytes` отбрасывается с флагом.
8. **`dispose()` идемпотентен** и не оставляет ни таймеров, ни слушателей.

## Почему не WebP

Playwright `page.screenshot` поддерживает только `png` и `jpeg`. Формат не подменяется:
поле называется `screenshotBase64` + `screenshotMimeType`, чтобы контракт не врал.

## Пересечения

- `@zcode/shared` (`browser-use/observation`): схема наблюдения — единственный источник
  типов для адаптера и потребителей.
- `adapters/browser` (контроллер CDP): вызывает `beginAction` перед командой и
  `observe` после, вкладывая результат в `BrowserCommandResult.observation`.
